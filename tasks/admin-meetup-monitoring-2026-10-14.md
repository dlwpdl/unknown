# 관리자 모임 모니터링

## 후속: 운영자에게 필요한 정보 우선

사용자는 모임 ID처럼 개발자가 추적에 쓰는 값이 기본 화면에 너무 많이 보인다고 정정했다. 첫 진입은 운영 현황으로 바꾸고 신고·위험·대기 건수에서 해당 화면을 바로 연다. 회원 목록은6개 핵심 열만 표시한다. 회원·모임·대화의 기본 라벨에서 UUID를 제거하고, ID·IP·GPS 좌표·로그인 공급자 ID·이벤트 키·분석 실패 원문은 상세의 문제 추적/접속 정보 안에서 펼친다. 회원의 추가 프로필과 상세 활동 필터는 필요할 때 열며, 전체 기록과 원문·승인 검증·감사 기록·AAL2 권한은 보존한다. 숨긴 데이터가 삭제되거나 조회 권한이 축소되는 것은 아니다. 통계와 수익 페이지는 계속 접근할 수 있다.

## 후속: 모임 상세 연결과 어드민 리디자인

사용자가 모임을 누르면 모임과 대화를 함께 모니터링하고, 디자인 스킬로 버튼과 상세 화면을 다시 디자인하도록 요청했다. 어드민 공통 검색·필터·보조 버튼·상태 선택과 회원/신고 상세의 규격을 맞춘다. 모임은 제목 또는 행 클릭 → 전용 상세 → 모임 정보/참여 신청/대화 모니터링으로 연결한다. 목록 복귀 시 검색·필터와 키보드 초점을 보존한다.

기존 밝은 관리자 테마(흰색, 회색, 보라색 강조)와 시스템 한글 글꼴을 유지한다. 본문과 기록의 위계를 다시 배치하고, 신청 기록과 대화는 선택한 모임 ID로만 조회한다. 새 버튼은 기존 피드백을 사용하고 44px 영역, 초점 표시, 작은 화면 줄바꿈을 검증한다. 기존 회원 검토·신고 처리의 서버 권한/검증·감사 기록을 유지하며 실제 수정 조치는 하지 않는다.

design/Apple Design을 적용하고 실제 Mobbin [Meetup](https://mobbin.com/screens/371f3c48-4639-4864-870f-f33bcf921a7e)의 작은 상태 선택, [Sprig](https://mobbin.com/screens/0e784aaf-7036-4281-8121-9666955f5a55)의 행 중심 목록, [DoorDash Merchant](https://mobbin.com/screens/12062d7c-488e-4f2e-8310-ac7c70982bb5)의 상단 메뉴와 펼친 상세를 확인했다. BrandKit의 현재 나이트 팔레트는 공개 앱용으로 대조했고 관리자 밝은 테마는 별도로 유지한다. Kroma는 Serper 키가 없어 결과를 얻지 못했으므로 참고 근거에 포함하지 않는다. 이미지 생성은 해당 없음.

검증 순서: 클릭/대화 범위/늦은 응답 검사 → 기존 컴포넌트와 CSS 수정 → HTML 시안의 실제 렌더 검수 → 타입·전체 검사·export → Orca의 실제 관리자 화면 확인.

사용자 요청: 어드민 대시보드에서 빠진 모임 모니터링을 추가한다.

- 콘텐츠·회원 메뉴와 화면 검색에 모임을 추가한다. 일회성·지속 모임, 게시 상태와 모집 상태, 도시·일정·주최자·참여 인원을 표시한다.
- 전체 모임을 서버에서 제목·도시·구분으로 검색하고 50건씩 조회한다. 최근 게시글 50건만 필터링하지 않는다.
- 선택한 모임의 본문, 신청자와 승인·대기·거절·취소 기록, 해당 모임 대화의 메시지를 페이지 단위로 조회한다. 회원 이름은 기존 회원 상세에 연결한다.
- 기존 posts/meetup_requests/conversations/messages RLS와 AAL2 관리자 세션을 사용한다. 기존 log_admin_access의 posts/conversations 범위에 모임 ID를 기록하고 감사 기록 실패 시 조회를 중단한다. 새 DB 권한·RPC·서버·종속성은 필요 없다.
- 조회·모니터링을 구현한다. 모임 상태 변경이나 신청 승인·취소는 이번 요청의 범위에 포함하지 않는다.
- 순서: 조회 경계 검사 → API와 메뉴 → 목록·상세·피드백 → 타입·전체 테스트·관리자 export → 실제 Orca 화면과 HTML 시안 확인.

디자인: Apple Design의 정보 우선순위와 키보드·초점·상태 표시를 적용한다. Mobbin에서 실제 [Meetup 이벤트 목록](https://mobbin.com/screens/acefe8c4-744e-4089-a7be-d6703dd3251e)과 [Sprig 이벤트 목록](https://mobbin.com/screens/0e784aaf-7036-4281-8121-9666955f5a55)을 확인했다. 검색·필터 한 줄, 일정·인원·상태 중심 표, 작은 화면 카드, 기존 관리자 밝은 테마와 공용 컨트롤을 재사용한다.

## 적용과 검증

기존 관리자 export에 반영했고, Orca의 Git → gling에서 모임 메뉴가 실제로 보이는 것을 확인했다. 운영 데이터 모임11건, 선택 모임 대화17건, 제목 검색1건을 정상 조회했다. 신청 목록의 빈 상태도 확인했다. DB/권한 변경이나 모임 상태·참여 신청의 수정은 하지 않았다.

- 전체 Node 검사:804개 통과,1개 건너뜀,실패0. 타입 검사와 새 파일 ESLint(오류·경고0), 관리자 export 통과.
- 조회 검사는 감사 기록 실패 시 차단, 전체 모임 검색/페이지, 이전 필터 응답 무시, 신청 상태 유지, 해당 모임 대화만 조회하는 경계를 검증한다.
- HTML 시안은1440/768/390px에서 가로 넘침0, 보이는 버튼44px 이상. 실제 모임/회원 데이터가 아닌 예시 데이터임을 표시했다.
- 시안: `output/design/admin-meetup-monitoring.html`. 상세 기록: `/Users/ash/Library/Application Support/gling/operations/admin-meetup-monitoring-20261014/implementation-check.json`.


## 최종 운영자 화면 확인

기본 진입을 운영 현황으로 바꾸고, 과거 처리한 신고의 전체 편집 화면을 첫 화면에서 빼서 미처리 요약과 전체 보기만 남겼다. 회원 목록은6개 열/실제50건을 확인했고, 회원 상세의 기본 화면에서 UUID가 보이지 않는 것과 접속 정보 펼침 후 원본 ID/IP를 확인할 수 있는 것을 검증했다. 모임11건 → 해당 대화방1개 → 메시지17개 연결도 실제 세션에서 확인했다. 현재 Orca의 Git → gling에는 운영 현황을 남겼다.

전체 검사824개 통과·기존2개 skip·실패0, 변경 후 보강 검사와 타입·lint·export 통과. 기존 서버를 재사용하고 이전 export 및 열린 탭의 파일을 보존했다. 시안1440/768/390px 가로 넘침0·버튼44px 이상, ID 기본 숨김/펼침 확인. 실제 제재·승인·삭제는 실행하지 않았고 DB/권한/자동화/스토어 제출은 변경하지 않았다. 근거는 기존 operations 폴더의 redesign/delivery-check.json이다.

# Spec: 리스팅 글과 묶인 대화 (렌트·중고·차량)

Owner request (2026-09-14): 렌트·중고·차량처럼 "구하거나 파는" 글을 커뮤니티에 올릴 수 있게 하고, 그 글에서 시작한 대화는 1:1 관계 슬롯을 쓰지 않게 한다. 단, 슬롯 면제를 악용해 일상 대화를 이어가는 것과 업자의 도배는 구조로 막는다. 사용자가 "목적"을 선언하는 UI는 두지 않는다.

## 원칙

- 규칙은 카테고리가 아니라 **글 종류**를 따른다. 카테고리(주거·이동·쇼핑…)는 주제, 종류(`story`/`listing`)는 성격. 주거+이야기 = 시세 질문, 주거+리스팅 = 렌트 매물.
- 면제는 의도가 아니라 **구조**에 건다. 리스팅 대화는 짧고 만료되므로 슬롯이 필요 없다. 길게 이어가려면 슬롯을 낸다.
- 악용 감지 로직을 만들지 않는다. 만료·쿨다운·한도가 대신 처리한다.
- **멤버십 등급은 남에게 보이지 않는다.** 프로필·글·채팅 어디에도 결제 등급을 표시하지 않는다. 노출되는 것은 인증 뱃지(신뢰)와 업체 뱃지(소비자 보호), 리스팅 강조 표시(기능의 결과)만이다. 등급 이름은 본인 멤버십 화면과 결제 시트에만 등장한다.

## 글 종류

| | 이야기 글 `story` | 리스팅 `listing` |
|---|---|---|
| 작성 한도 | 기존 하루 1 / 2 / 5 (무료/플러스/프리미엄) | 하루 한도 없음. **살아있는 개수** 5 / 10 / 20 |
| 수명 | 계속 | 14일. 끌어올림 시 만료일이 다시 14일 뒤로 |
| 상태 | 없음 | `open → partial(일부 판매) → closed(거래완료/취소) → expired` |
| 마감 후 | — | 피드에서 내려가고 읽기 전용. "다시 열기"로 재활성(살아있는 개수 재차지, 끌올 기록 초기화) |
| 사진 | 4장 | 8장 (묶음 글은 사진이 목록) |
| 종류 변경 | 발행 후 불가 | 발행 후 불가 (잘못 골랐으면 삭제 후 재작성) |

작성 화면: 카테고리 선택 후 "어떤 글인가요?" 이야기 / 리스팅 한 번 선택. 기존 글은 전부 `story`.

리스팅 최소 필드: 가격(선택), 거래 지역(프로필 동네 기본값), 상태. 카테고리별 전용 폼은 만들지 않는다.

한도 도달 시: "살아있는 리스팅이 5개예요. 거래가 끝난 글을 마감하면 자리가 돌아와요" + 내 리스팅 목록으로 이동.

## 끌어올림

- 전 등급 **무제한**. 차이는 쿨다운만: 무료 24시간 / 플러스 18시간 / 프리미엄 12시간.
- 효과: 피드 정렬 기준(`bumped_at`)만 갱신, 작성일 표기는 유지("3일 전 작성 · 방금 끌어올림"). 만료일 14일 연장.
- 마감·만료된 글은 끌어올림 불가("다시 열기"가 그 역할). 살아있는 개수를 소모하지 않고, 연결 대화의 만료도 되살리지 않는다.
- 버튼은 리스팅 상세에서 작성자에게만. 쿨다운 중이면 비활성 + 가능 시각 표시. 검사는 서버.
- 강조 표시(카드 테두리·"추천" 라벨): 플러스 하루 1회, 프리미엄 상시. 1차 범위 밖, 자리만 비워둔다.

## 중복 글 방지 (새 글이 아니라 기존 글로 되돌린다)

1. 같은 작성자의 살아있는 또는 30일 내 마감된 리스팅과 **정규화된 제목이 같으면** 발행 거부 → "같은 글이 있어요: 끌어올리기 / 다시 열기".
2. 업로드 **사진 해시**가 기존 리스팅과 같으면 1과 동일하게 거부.
3. 제목 유사도 80% 이상은 경고만. 1차 범위 밖.

30일 지난 글은 새 글로 인정한다.

## 묶인 대화 `thread`

- 리스팅 상세의 "대화하기"는 `conversations.kind = 'thread'`. 이야기 글·프로필에서의 "대화하기"는 기존 `direct`.
- 슬롯 미사용. 종료 조건: 마지막 메시지 후 **72시간** 또는 글 마감(`closed/expired`) 후 72시간 중 먼저 오는 쪽. 종료 후 읽기 전용.
- "1:1로 이어가기": 한쪽이 제안, 상대가 수락하면 **양쪽 모두 빈 1:1 슬롯**이 있어야 `direct`로 전환. 전환 시 `thread`는 종료되고 이후 기존 규칙(슬롯 차감, 종료 시 24시간 잠금)이 적용된다.
- 우회 차단: 같은 두 사람은 7일 안에 다른 글로 다시 `thread`를 만들 수 없다(`relationship_cooldowns`에 `thread` 풀 추가). 한 글에 한 사람은 대화 하나. 하루 새로 열 수 있는 `thread` 5개.
- 첫 화면과 리스팅 상세 상단에 "직거래·선입금 금지" 고정 안내 한 줄. 사기는 시스템으로 막지 못한다.
- 댓글은 종류와 무관하게 기존대로 연다. 가격 협상은 대화로 유도하는 안내만.

## 채팅 탭

- 필터: 전체 / 모임 / 1:1 / **거래·문의** / 요청. 상단 슬롯 카드는 1:1 기준 유지.
- `thread` 행에는 "자리를 쓰지 않아요 · N일 후 종료" 한 줄.

## 업체 멤버십 (나중, 자리만 비워둠)

- 판매하는 것은 글 개수가 아니라 **표시된 자리**. 업체 리스팅은 "업체" 뱃지 필수, 메인 피드 6장당 1장까지, 나머지는 "업체 매물" 필터. 사업자/중개 라이선스 검증 후 관리자가 승인. 살아있는 개수 50.
- 1차에서는 `profiles`에 업체 여부 컬럼만 예약한다. 실제 업자 신고가 쌓이기 전에는 만들지 않는다.

## 데이터

- `posts`: `kind text default 'story'` (`story|listing`), `listing_status`, `price` (nullable), `expires_at`, `bumped_at`, `bump_count`, `image_hashes text[]`.
- `conversations.kind`에 `thread` 추가, `thread_post_id`, `last_message_at`, `expires_at`.
- `relationship_cooldowns.pool`에 `thread`.
- `tags`는 변경 없음(카테고리 축 유지).
- 트리거/RPC: 살아있는 리스팅 한도(`posts_membership_limit` 옆), 발행 시 중복 검사, 끌어올림 RPC(쿨다운 서버 검사), `thread` 생성·만료·전환 RPC, 피드 정렬 `coalesce(bumped_at, created_at)`.
- 만료 처리는 `pg_cron` 또는 기존 안전 점검 스케줄에 한 작업 추가.

## 구현 순서

1. DB: 컬럼·제약·한도 트리거·중복 검사·끌어올림 RPC + pgTAP.
2. DB: `thread` 대화 생성·만료·전환 RPC + pgTAP.
3. 앱: 작성 화면 종류 선택과 리스팅 필드, 상세의 상태·끌어올림 버튼, 내 리스팅 목록, 채팅 필터와 배너, 안내 문구.

Validation: `npm test`, `npm run typecheck`, `npm run lint`, SQL 테스트, 실기기 또는 시뮬레이터에서 리스팅 작성 → 한도 → 끌어올림 쿨다운 → thread 대화 → 72시간 만료(시각 조작) → 1:1 전환 흐름 확인.

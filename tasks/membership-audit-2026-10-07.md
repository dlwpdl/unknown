## 구매·복원·해지·만료

클라이언트가 tier·userId·receipt·expiry를 보내도 서버는 본인 세션 또는 인증된 webhook을 확인하고 RevenueCat의 현재 상태를 다시 읽는다. `apply_membership_snapshot` 실행은 service_role만 가능하며 membership 테이블은 anon·authenticated의 읽기·쓰기 모두를 거부한다. 환불·만료·지원하지 않는 스토어·허용되지 않은 Sandbox는 권한을 열지 않는다. 갱신 취소는 남은 이용 기간을 유지한다. 오래된 snapshot은 최신 상태를 덮어쓰지 않고, 서버 시간만으로도 만료 뒤 무료로 전환된다. provider 오류는 기존 유료 상태를 강제로 무료로 만들지 않는다.

클라이언트는 계정별 snapshot·상품과 SDK 작업 queue를 분리한다. 다른 스토어의 활성 구독은 추가 구매를 차단하며 Android 변경은 DEFERRED로 예약하고 안내한다. 계정 삭제 전에 스토어 구독이 자동 해지되지 않음을 알리고 구독 관리 버튼을 제공한다. RevenueCat 고객 데이터 삭제와 스토어 해지는 별개다.

## 업체 Basic·Trial·Pro

개인 Premium은 업체 Pro를 자동으로 부여하지 않는다. 업체 상태와 그 도시의 날짜를 사용한다. `trial`과 유효한 `trial_ends_at`은 Trial, `paid`와 유효한 `workspace_until`은 Pro이며 날짜가 없거나 지나면 Basic이다. 새 체험은 오늘부터 오늘+13일까지 14개 도시 날짜이며 자동 청구가 없다. 업체 가격·체크아웃은 미설정이다.

Basic은 원가 계산, 품목과 개별 입출고, 초안과 개별 승인 작업을 유지한다. 재고 2개 이상 일괄 변경·원고 2개 이상 일괄 승인은 Trial/Pro의 서버 guard가 필요하다. 게시에는 업체 소유 확인·허락·원고 승인과 기존 `create_post`의 개인 계정 게시·안전 규칙이 적용된다. 업체 등급은 개인의 모임·대화 자리를 추가하지 않는다. 품목 500개, 초안 100개, 배치 50개, 업체 목록 조회 50개, 보고서 조회 최근 12개 상한을 확인했다. 계정 삭제는 비공개 품목·초안을 지우고 업체 연결·접근 기간을 해제한다.

0119는 최초 운영 schema 조회에는 없었다. 신규 업체 권한은 로컬 코드·DB 검사 범위로 기록했다. 업체 native UI와 실제 운영 배포는 root의 최종 결과에 따라 별도로 갱신해야 한다.

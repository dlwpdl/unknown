# 홍보 크레딧 화면 설계 · 2026-09-10

상태: 사용자 추가 지시에 따라 출시 앱에는 크레딧·끌어올리기를 완전히 숨긴다. 이번에 작성한 화면은 개발 빌드에서 `EXPO_PUBLIC_PROMOTIONS_PREVIEW=1`을 명시한 경우에만 열 수 있다. 기본값과 모든 출시 빌드에서는 프로필 메뉴·내 글 진입 버튼이 없고, 직접 경로에 접근해도 프로필로 돌아간다. 결제·홍보 판매를 개시한 상태가 아니다. 아래는 향후 개발 검토용 설계다.

## 실제 확인한 참고 화면

- [Blank Street Wallet · Mobbin](https://mobbin.com/screens/e81cb598-360f-4240-aef8-1f53b0e07dd0): 상품 사진 아래 Available Balance, Manage·Add Funds 버튼, 아래쪽 Order history에 주문·충전 항목과 금액이 보인다. 잔액·충전·사용 내역의 정보 순서만 참고한다. 커피 구매 지갑의 정책을 글링의 인앱 재화 정책으로 해석하지 않는다.
- [Zopa Bank 계좌 닫기 확인 · Mobbin](https://mobbin.com/screens/fcb8c082-214f-4d82-817a-5c6207e0cdd2): 뒤로가기, 중앙 경고 아이콘·질문, 하단 Close my Smart Saver 버튼을 실제 확인했다. ‘계속 진행/나중에’ 두 선택지는 없고 계좌 폐쇄라는 다른 맥락이므로 글링의 비차단 안내 패턴으로 채택하지 않는다. 이번 조사에서 Mobbin 화면은 두 개만 열람했다.
- [Wallet balance concept · Pinterest](https://www.pinterest.com/pin/844493676473080/): 원본 이미지를 내려받아 직접 열람했다. 잔액, Send·Withdraw, Transaction History가 보이는 흰색 유리 효과 시안이다. 큰 잔액과 낮은 대비, 송금·출금 버튼, 장식적인 재질은 글링에 가져오지 않는다. 잔액과 내역이 연결된다는 정보 구조만 보조 참고한다.

BrandKit은 이번 세션의 기존 조회에서 YourBrand 기본 자료였고 Kroma는 SERPER_API_KEY 미설정으로 확인되어 반복 호출하지 않았다. 글링의 실제 브랜드 근거는 승인된 B 시안, src/constants/theme.ts, src/assets/brand의 기존 자산이다. Apple 디자인과 frontend-ui-engineering 스킬의 선택권·맥락 가까운 상태 안내·명확한 피드백·접근성 원칙을 적용한다.

## 가장 작은 진입 구조

1. `src/app/profile/index.tsx`의 기존 멤버십 메뉴 바로 아래에 ‘홍보 크레딧’ 행을 추가한다. 별도 하단 탭이나 전역 잔액 위젯은 만들 필요가 없다.
2. `/profile/promotions` 한 화면에 잔액·충전 상품·사용 내역을 배치한다. `postId`로 진입하면 같은 화면 안에서 해당 글과 홍보 시작 설정도 보여준다. 같은 화면에서 본인의 게시된 글을 선택할 수 있다.
3. `src/components/post-detail.tsx`의 PostCard 아래에 로그인한 작성자에게만 ‘이 글 끌어올리기’를 둔다. 서버에서도 글 소유권과 홍보 가능 상태를 확인한다. 화면 이동 전에 상세 모달을 닫는 기존 라우팅 패턴을 재사용한다.
4. `src/app/profile/_layout.tsx`의 기존 Stack에 경로를 등록하고 멤버십 화면과 같은 reducedMotion 설정을 사용한다.
5. `src/components/feed-screen.tsx`의 글쓰기 진입과 생성 흐름은 독립적으로 유지한다. 글이 실제로 생성된 다음 글 상세에서 홍보를 시작한다. 구매 잔액을 먼저 가진 사용자도 이 경로를 쓸 수 있다. 글 생성 실패가 크레딧 차감으로 이어지지 않는다.

## 화면 순서와 문구

- 잔액: ‘내 홍보 크레딧’ / ‘1,800 크레딧’ / ‘게시글을 더 많은 사람에게 알릴 때 사용해요.’ 숫자는 기존 tabular-nums 패턴을 쓰고 원화·달러 잔액처럼 표시하지 않는다. 예시 숫자는 실제 데이터로 대체한다.
- 충전: 실제 스토어 상품의 크레딧 수량과 현지 가격을 함께 표시한다. ‘900 크레딧 · CA$… 구매’처럼 사용자가 얻는 수량과 지불 가격을 구분한다. 판매 금액·크레딧 환산율은 이 디자인 문서에서 확정하지 않는다.
- 글이 선택된 경우: 제목·도시 → 추가 홍보 노출 수량과 필요한 크레딧 → 현재 새 대화 수락 가능 수 → ‘크레딧 사용하고 홍보 시작’. 자연 노출과 추가 홍보 노출은 관리 화면에서도 분리한다. 추가 노출이 고유 방문자 수나 문의 성사를 보장하는 것처럼 쓰지 않는다.
- 내역: 충전·홍보 사용·반환을 시간과 수량으로 보여준다. 상세 결제 식별자는 기본 화면에 노출하지 않는다. 잔액과 내역 조회 실패를 ‘0 크레딧’, ‘내역 없음’으로 바꾸지 않는다.

빈 슬롯이 0개이면 홍보 설정 안에 안내를 먼저 표시하고, 최종 시작 동작에서 최신 서버 상태를 다시 확인한다.

> 지금은 새 대화를 수락할 자리가 없어요.
> 대화 요청은 받을 수 있지만, 자리가 생긴 뒤 수락할 수 있어요. 홍보는 계속할 수 있어요.

선택은 ‘그대로 홍보 시작’과 ‘홍보 나중에 하기’. 두 번째 선택은 이미 게시된 글과 크레딧을 그대로 보존한다. 구매 자체는 슬롯 부족으로 막지 않는다. 홍보 중 슬롯이 차도 자동 중단하지 않는다. 공론화·정보 전달처럼 읽히는 것이 목적인 글도 있다.

## 현재 코드에서 주의할 경계

- 현재 `MembershipSnapshot`은 `conversationPeriod: day | active`, `conversationsUsed`만 제공한다. 지금 배포된 일일 신규 대화 수를 ‘새 대화 수락 가능 수’로 바꿔 표시하면 안 된다. 실제 활성 슬롯과 24시간 잠금을 함께 반영하는 서버 상태가 필요하다.
- 서버 슬롯 기능이 아직 준비되지 않았으면 그 사실을 표시한다. 일시 조회 실패이면 ‘대화 자리를 확인하지 못했어요’와 재시도를 제공한다. 실패를 0개 또는 충분한 자리로 가정하지 않는다. 이 상태의 홍보 계속 선택도 사용자의 의사를 보존한다.
- 결제 완료 화면과 서버 잔액 반영은 구분한다. 검증 중이면 ‘구매 내역을 확인하고 있어요’로 안내하고, 재구매를 권하지 않는다. 결제 취소는 오류·성공으로 표시하지 않는다.
- 홍보 시작 응답을 잃었을 때 재시도는 같은 요청을 조회·재사용해야 한다. 사용자의 반복 탭으로 이중 차감되면 안 된다. 잔액 사용 성공·실패는 서버 확정 후 표시한다.
- 글 검토·숨김·삭제 시 홍보 가능 상태와 잔여 수량 처리도 서버 정책을 따른다. 크레딧 구매가 기존 전체 콘텐츠 안전 모니터링이나 게시 한도를 면제하지 않는다.

## B 컨셉과 검증

기존 paper 배경·ink 텍스트·인주색 주요 버튼, 16pt 기본 여백, 12pt 카드 모서리, 기존 ThemedText·ThemedView·useTheme를 재사용한다. 코인 일러스트, 그라데이션 잔액 카드, 새로운 애니메이션 라이브러리는 필요 없다. 크레딧 화면에서는 작은 상태 행과 분명한 버튼 한 개가 우선이다.

구현 후 320px 폭·큰 글자·어두운 모드에서 줄바꿈과 대비, 44pt 터치 영역, 뒤로가기 및 포스트 선택 유지, 화면 낭독 상태 알림, 모션 감소 설정을 확인한다. 금전 로직 확인은 중복 결제 이벤트·동시 사용·타인 글 사용·응답 유실 재시도·환불 조정이 포함되어야 한다. 웹 미리보기만으로 실제 인앱결제 검증을 완료했다고 하지 않는다.

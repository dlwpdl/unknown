# 글링 멤버십 화면 — 구현용 디자인 메모

작성: 2026-09-09. 범위: 기존 종이색·인주색 컨셉을 유지하는 구독 화면과 진입점. 후속 지시에 따라 `src/app/profile/membership.tsx`, 프로필 메뉴와 Stack route에 화면 구현을 추가했다. 가격·결제·서버 권한은 별도 구현 중인 membership provider 계약을 사용한다.

## 결정할 수 있는 최소 화면

프로필 메뉴에 **멤버십**을 추가하고 `/profile/membership` Stack 화면 하나에서 현재 등급, 혜택 비교, 구매·복원·관리를 해결한다. 피드 진입을 가로막는 강제 결제 화면은 만들지 않는다. 작성·모임·대화 한도에 도달했을 때 같은 화면으로 이동한다.

화면 순서:

1. 기존 네이티브 뒤로가기 + 제목 `멤버십`.
2. `나에게 맞는 만큼, 글링` 제목과 `글링은 무료로도 함께할 수 있어요.` 안내. 현재 등급을 분명히 표시하고, 서버가 반환한 사용량이 있을 때만 오늘 글·참여 모임·1:1 한도를 표시한다.
3. `베이직 · 무료`의 1/3/3 혜택을 짧은 행으로 먼저 보여준다. 유료 두 등급은 **프리미엄 → 플러스** 순서의 세로 선택 카드로 표시한다. 프리미엄에 `더 넉넉하게` 라벨과 인주색 테두리를 사용한다. 선택한 카드에는 체크와 `선택됨`을 함께 표시한다. 무료를 구독 상품으로 취급하지 않는다.
4. 유료 카드마다 등급명, 스토어에서 불러온 전체 청구 가격·기간, 같은 순서의 세 가지 숫자를 표시한다. 캐러셀이나 좁은 4열 비교표는 피한다. 작은 화면과 큰 글자에서도 카드가 세로로 늘어난다.
5. 월/년 등 주기 선택은 실제 승인·등록된 상품이 여러 주기일 때만 노출한다. 가격, 기간, 무료 체험과 할인율을 임의로 넣지 않는다.
6. 선택 등급·주기·전체 청구액을 구매 버튼 가까이 다시 보여준다. 버튼 이름은 `프리미엄 구독하기`처럼 실제 선택을 설명한다. 아래에 자동 갱신 및 스토어에서 해지할 수 있다는 문구를 둔다.
7. `무료로 계속하기`, `구매 복원`, `구독 관리`, `이용약관`, `개인정보처리방침`을 읽을 수 있는 크기로 제공한다. 무료로 계속하기는 뒤로 이동하며 기존 구독을 해지하지 않는다. 유료 이용자의 해지는 구독 관리로 안내한다.

확정된 수치:

| 혜택 | 베이직 | 플러스 | 프리미엄 |
| --- | ---: | ---: | ---: |
| 하루 글 작성 | 1 | 2 | 5 |
| 모임 | 3 | 5 | 10 |
| 1:1 대화 | 3 | 5 | 10 |

모임·1:1 대화의 집계 단위는 사용자 답변 및 서버 정의와 정확히 맞춰 최종 문구를 정한다. `1:1 대화 10개`를 일일 새 대화 시작과 동시 보유 대화 양쪽 의미로 섞어 쓰지 않는다. 광고 제거, 홍보 노출권, 무제한 답장 등 미확정 혜택은 판매 문구에 추가하지 않는다.

## 기존 코드에서 재사용

| 목적 | 파일 | 적용 |

| 네이티브 탐색 | `src/app/profile/_layout.tsx` | 기존 Stack의 배경·back·header 설정을 그대로 사용. 새로운 탭이나 수제 바텀시트 불필요. |

| 피드백 | `src/lib/interaction-feedback.tsx` | 등급 선택에 `play('selection')`, 검증된 구매 완료에 `play('success')`. 사용자의 소리·햅틱 설정을 존중. |

선택 카드는 `Pressable`의 즉시 pressed 피드백과 `accessibilityState.selected`를 사용한다. 터치 영역 최소 44px, 버튼 disabled/busy 상태를 접근성에도 반영한다. 색만으로 현재·선택 상태를 전달하지 않는다. 구매 대기 중 추가 구매 탭은 막되 뒤로가기·취소 등 탐색은 유지한다. 스토어 결제 시트와 기존 Stack이 기본 전환을 담당하게 한다.

## 상태와 결제 설명

- **상품 로딩:** 현재 무료 혜택을 계속 보여주고 가격 위치만 로딩. 숫자 가격을 0원으로 대체하지 않는다.
- **설정 미완료·불러오기 실패:** `구독 상품을 불러오지 못했어요`와 재시도. 구매 불가 이유를 보여주고 실제 상품 없는 구매 CTA는 비활성화한다. 공개 사용자 화면에 RevenueCat API 키·환경 변수 등 구현 용어는 노출하지 않는다.
- **사용자 결제 취소:** 실패 경고를 과장하지 않고 선택한 화면으로 돌아온다.
- **결제 보류·서버 반영 지연:** 확인 중 상태. 버튼 탭이나 로컬 SDK 콜백만으로 서버 제한을 먼저 풀지 않는다.
- **활성 구독:** 현재 등급과 실제 만료/갱신 정보, 구독 관리 진입. 해지 예약은 남은 이용 기간까지 유료 혜택이 유지됨을 구별한다.
- **복원 결과:** 활성 구매가 없을 때와 복원 실패를 구분한다. 계정 전환 후 다른 계정의 등급을 잠시 보여주지 않는다.
- **탈퇴:** 계정 삭제와 스토어 구독 해지를 같은 작업으로 오인하지 않도록 구독 관리 진입이 필요하다. 현재 `legal-documents.ts`에는 구독 설명이 없으므로 실제 판매 전에 구독·결제 정보 처리 문구를 함께 검토한다.

Apple 공식 안내는 구매 화면에 구독명·기간·혜택·현지화된 전체 갱신 가격·복원 경로를 요구하며, 연간 청구액이 월 환산액보다 두드러져야 한다고 설명한다. [Apple 구독 안내](https://developer.apple.com/app-store/subscriptions/)

## 연결 도구 조사와 시각 근거

- **BrandKit:** `get_brand_overview`, `get_colors_and_type(product)` 호출. 현재 반환은 `Your Brand` 기본 템플릿과 검정/흰색 기본 토큰이다. 글링으로 확인된 브랜드 자료가 아니므로 덮어쓰지 않고 프로젝트의 기존 토큰을 유지한다.
- **Mobbin:** 아래 세 결과의 실제 인라인 이미지를 직접 확인했다. 텍스트 메타데이터만으로 화면을 추정하지 않았다.
  - [Lifesum 구독 화면](https://mobbin.com/screens/43d1ac57-cca2-4939-ba2e-bb0d4d6c3fbb): 무료·프리미엄 비교 열과 강조된 유료 선택, 아래 복원 링크가 보인다. 무료 비교와 복원 경로를 채택한다. 할인 배너·3개 결제 주기·희미한 비선택 가격은 글링에 복제하지 않는다.
  - [Coffee Meets Bagel 등급 비교](https://mobbin.com/screens/8f7f70d8-4d92-433c-a39e-160568d996cc): 두 유료 열에서 같은 기능을 행으로 맞춰 비교한다. 글링도 두 유료 카드에서 같은 혜택 순서를 유지한다. 일 환산 가격을 대표 가격으로 쓰는 표현은 따르지 않는다.
  - [SCMP 등급 비교](https://mobbin.com/screens/0b41f5dd-af78-409d-b708-f4e43ff52554): 그룹으로 묶은 기능 행과 화면 상단의 복원 링크가 보인다. 글링은 확정된 세 항목만 담아 긴 비교표를 줄인다.
- **Pinterest:** 검색 후 [PERKi 레퍼런스](https://www.pinterest.com/pin/102808803989817847/) 원본 이미지를 내려받아 직접 확인했다. 크림색 배경, 붉은 굵은 문구, 하단의 뚜렷한 버튼 위계가 글링 기존 톤과 맞는다. 로그인 목업이므로 구독 동작의 근거로 쓰지 않고 색·위계만 참고한다. 검토 이미지: `/tmp/gling-subscription-pinterest-reference.jpg`(임시 파일).
- **Kroma:** `kroma_find_ui_inspiration` 실행했으나 `SERPER_API_KEY` 미설정 오류로 결과를 받지 못했다. Kroma 레퍼런스를 확인했다고 주장하지 않는다. 별도 유료 서비스 가입 없이 위 Mobbin 이미지와 Apple 공식 문서로 구독 흐름을 검토했다.

구현 후 확인: iPhone X 폭 375px 및 320px, 큰 글자·다크 모드, 가격이 긴 통화, VoiceOver 선택·복원, 로딩/오류/취소/보류/복원/해지예약 상태. 결제 성공 검증에는 실제 네이티브 테스트 빌드와 sandbox 구매가 필요하며 웹 미리보기로 대체하지 않는다.

검증 경로: 현재 앱 개발 서버는 `expo start --web --port 8091`이고 화면 주소는 `http://localhost:8091/profile/membership`이다. `8092`는 `output/design` 정적 리포트 서버다. 기존 로그인 또는 `/auth/review`의 승인된 심사 계정으로 로그인한 후 멤버십을 확인한다. 웹의 `_layout.web.tsx`에도 실제 MembershipProvider 연결이 필요하다. 화면 진입 시 `useFocusEffect`가 로그인 여부를 확인한 뒤 서버 사용량을 새로 읽는다.

코드 검증: provider 연결 이후 부모 작업의 `npm run typecheck` 통과 보고를 확인했고, 이 작업에서 UI와 feed 수정 파일의 targeted ESLint 및 `git diff --check`를 통과했다. 실제 계정으로 화면 렌더와 native sandbox 구매 검증은 부모 작업에서 이어간다. Provider 검토 중 구매 완료 후 서버 반영 지연·승인 대기·동시 refresh의 상태 처리를 보완할 항목으로 전달했다.

후속 흐름: `notice`에도 다시 확인 버튼을 표시한다. `feed-screen.tsx`의 사전 한도 안내와 서버 한도 거절은 같은 Alert를 사용하고 닫기·멤버십 보기 선택을 제공한다. 사용자가 선택해야 이동하며 작성 중 초안은 지우지 않는다. 기존 작성량 변경 이벤트를 feed에서도 수신해 구독 반영 후 서버 한도를 다시 읽도록 연결했다. 검증 시 구독 전 하루 한도에 도달한 계정이 구독 후 앱 재시작 없이 추가 글을 작성할 수 있는지도 확인한다.

2026-09-10 모임 한도 통합: 모임 탭에 `MyMeetups`를 붙여 내 운영·참여·신청 대기를 공개 모임과 구분했다. 기존 RLS 조회로 현재 사용자와 published/open 조건을 제한하고, 역할에 따라 모임 종료·나가기·신청 취소 확인 후 `leave_meetup`을 호출한다. 종료된 글은 역사로 남지만 참여 버튼·모임 소개·탐색에서 제외된다. 기존 이벤트 패턴으로 생성·신청·승인·종료 이후 목록을 갱신하며, 본인 한도와 신청자 한도를 구분해 승인자에게 잘못된 구독 구매를 권하지 않는다. 11개 community/feed/quota 테스트에서 종료 글 보존, 숨김·종료 모임 제외, 역할 구분, 나가기 실패 전달과 오류 분류를 검증했다. 실제 운영자 종료/참여자 나가기/대기 취소와 취소 버튼의 무변경 동작은 부모의 앱 검증에 포함한다.

# 모임 프로필·상세·신청·검토 재디자인 — 2026-10-06

사용자가 요청한 범위는 Hinge처럼 즐겁게 작성하는 모임 프로필, 핵심 정보를 묶은 상세, 모임장 질문에 답한 뒤 프로필을 공유하는 신청, 신청자를 중심에 둔 검토, 정확한 참여 상태·오류 안내다. 현재 모임 탐색 화면의 방향은 유지한다.

## 화면과 동작

- 프로필: 사진·한 줄 소개, 첫 문답, 두 번째 문답, 관심사, 공유 카드의 5단계. 뒤로 이동해도 입력을 보존한다. 예시를 고른 뒤 직접 편집할 수 있다. 기존 네 필드와 사진·도시 저장 방식을 유지한다.
- 상세: 날짜·시간, 활동 지역, 호스트를 포함한 정원을 아이콘이 있는 정보 묶음으로 보여준다. 정확한 장소가 없으면 주소를 만들어내지 않고 승인 후 안내라고 표시한다. 중복된 참여 모듈을 숨기고 신청 상태에 맞는 행동을 정보 뒤에 둔다.
- 신청: 모임 요약 → 모임장 질문·답변 → 공유 프로필 확인 → 공유 동의 → 신청. 프로필을 접어도 답변·동의를 보존하며, 제출 오류가 입력을 지우지 않는다.
- 검토: 신청자 사진·닉네임을 가장 크게 보여주고 모임명은 문맥 정보로 줄인다. 신청 답변과 공유 프로필을 같은 화면에서 바로 읽는다. 승인 primary와 거절 보조 행동은 아래에 둔다.
- 상태: 대기·승인·거절·취소와 정원 마감·모집 마감·일정 종료·통신 오류를 구분한다. 대기는 자리 예약이 아니며 정원 마감과 함께 존재할 수 있다. cancelled의 실제 원인은 서버에 없으므로 자발적 취소라고 단정하지 않는다.
- 승인 실패: 처리 실패를 프로필 조회 실패처럼 표시하지 않는다. 서버가 다시 허용한 프로필만 유지하고 취소·권한 종료 때는 폐기한다. 이미 처리된 신청은 공개된 상태만 확인한다.

## iOS 후속 검증 — 2026-10-06

iOS 26.5의 GLING Journal 시뮬레이터에서 설치된 앱을 실행했다. 앱 소스 사본과 로컬 API를 연결했으며 실제 계정·Supabase 요청·서버 데이터는 사용하지 않았다. 원래 Metro 8081은 유지하고 테스트 사본만 8084/8767에서 실행했다.

- 5단계 작성·관심사 선택·미리보기·저장을 확인했다. 키보드가 열린 프로필 직접 입력란이 고정 하단 버튼 뒤로 가려지는 문제를 재현하고, 기존 ScrollView를 입력 포커스·레이아웃 변경 때 이동하도록 수정했다. 긴 답변은 기존 네이티브 TextInput의 내부 스크롤을 사용하며 높이를 128dp로 제한했다.
- 키보드를 계속 열어 둔 채 짧은 답변을 200자 이상의 답변으로 늘렸을 때 입력란과 버튼 전체가 보이는지 확인했다. 실제 Keyboard 이벤트의 키보드 위치와 접근성 좌표를 비교하는 scripts/check-meetup-keyboard.py 검사도 통과했다. 신청 답변 입력란도 같은 검사에 통과했다.

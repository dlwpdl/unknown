- Android's generated splash theme referred to a nonexistent `splashscreen_logo` because the launch design deliberately has no static logo. The existing launch plugin now sets `windowSplashScreenAnimatedIcon` to Android's transparent resource. The generated-resource check failed before this fix and passes after it.
- Apple rejected upload 12 with error 90683, missing `NSMotionUsageDescription`. Expo Location 57.0.17 includes CoreMotion symbols even when `motionUsagePermission: false` removes the plist string. Build 13 supplies an explicit, truthful compatibility explanation: Gling does not request or collect motion/fitness information. App code only calls foreground location APIs; no motion API or background location was enabled. Generated Info.plist contains the string, has build 13, and has no Always-location permission or location background mode. [Expo 57 location configuration](https://docs.expo.dev/versions/v57.0.0/sdk/location/).
- JavaScript checks: 112/112 passed. Typecheck, lint, public web export and public-admin-route exclusion check passed. Android AAB/APK release builds passed. iOS 12 archive/export passed; its upload failed as described above.
- `npm audit`: zero high/critical, 15 moderate findings cascading from `decode-uri-component` and `uuid` advisories. The former concerns malformed percent-decoding input; the latter concerns caller-supplied buffer bounds in UUID v3/v5/v6. No blanket `audit fix` was applied: npm's proposed dependency changes include downgrading Expo. These moderate advisories remain unresolved; do not call the dependency audit clean.

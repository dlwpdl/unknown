# 글링 성능 개선 구현 계획

승인 근거: 2026-09-12 성능 점검 결과에 대한 사용자의 “전체 최적화 해줘”. 점검 기록 `tasks/performance-audit-2026-09-12.md`를 요구사항으로 삼는다.

목표: 이용량 증가에 따라 불필요하게 늘어나는 조회·렌더링·이미지 전송·글 저장 작업을 줄이고 재현 가능한 검증을 남긴다. 기존 기능, 디자인, 접근 권한 및 ADR-0001의 전체 안전 모니터링은 보존한다. Expo 57 / RN 0.86 / Supabase를 유지하며 유료 서비스는 추가하지 않는다.

## 작업과 검증

- [ ] 채팅: 전체 이력 반복 조회를 제한된 페이지로 변경. 활성/요청 목록이 과거 이력에 가려지지 않게 서버 필터 제공. 선택한 대화 딥링크 유지. 실시간 이벤트의 중복 조회를 합치고 이전 응답이 새 상태를 덮지 않게 한다. 파일: `community-data.ts`, 채팅 화면/방, 새 SQL migration 0043 및 Node/SQL 테스트. 500개 이력에서도 한 페이지 갱신 조회량은 일정해야 한다.
- [ ] 댓글: 기존 FlatList로 루트·답글·더 보기 행을 가상화. 알림 댓글 위치, 답글 대상/접기, 삭제·차단·좋아요·키보드를 보존. 파일: `post-detail.tsx`, 필요한 댓글 행 계산 helper와 동작 테스트. 1천 개 댓글에서도 전체 뷰가 마운트되지 않아야 한다.
- [ ] 사진/피드: 기존 설치 모듈부터 확인하여 업로드 이미지 크기를 줄이고 캐시 재사용을 검증. 품질·가로세로 비율·방향을 보존한다. 검색과 피드 페이지의 중복/오래된 응답도 보호한다. 파일: 이미지 처리와 피드 데이터/화면/카드 및 관련 테스트. 새 의존성은 기존 API로 해결 불가능한 경우만 검토한다.
- [ ] DB/알림: 별도 로컬 DB에서 기준값을 측정하고 새 글 알림 생성을 제한된 백그라운드 배치로 전환한다. 동의·선호 도시·차단·탈퇴·중복 방지·접근 권한을 처리 시점에도 검사한다. 기존 pg_cron을 재사용한다. 파일: migration 0042, SQL 테스트/벤치마크. 카테고리/검색/인기 해시태그 조회는 측정 후 필요한 최적화만 반영한다.
- [ ] 통합: `npm test`, `npm run typecheck`, `npm run lint`, SQL 전체 회귀, 웹 export 및 가능한 iOS/Android 검증. 각 변경과 수치, 미검증 범위를 보고한다.

## 작업 경계

현재 `mobile-app` 체크아웃의 앱 소스는 깨끗하며 스토어 빌드는 별도 체크아웃이다. 다른 작업의 marketing/release/tasks 변경은 유지한다. 각 구현 작업은 서로 다른 소스를 소유하고 커밋은 통합 시 순차 진행한다. 583E 시뮬레이터와 3100 스트림, 54321 어드민 서버는 유지한다. 카테고리 재편과 위치 카드 이동은 이번 성능 개선에 포함하지 않는다.

외부 부하 시험이나 무분별한 캐시·인덱스 추가는 하지 않는다. DB 배포는 로컬 회귀와 기존 앱 호환 검증 후 적용한다. 새 테스트는 실제 함수·쿼리 계약 및 실패 경로를 검증한다.

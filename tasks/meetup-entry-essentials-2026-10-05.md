# 모임 필수 진입 흐름 보완 — 2026-10-05

사용자가 승인한 범위: 1. 모임용 프로필, 2. 모임 탐색·상세, 3. 가입 요청·승인.

## 목표와 범위

- 기존 계정의 닉네임·사진·활동 도시를 프로필 작성과 공유 미리보기에 함께 보여준다. 소개·관심사·기존 두 문답은 현재 저장 계약을 재사용한다.
- 지역·관심사 검색과 기존 필터를 유지하며, 모임 상세에 정원·가입 방식·프로필 공개 범위를 분명히 표시한다.
- 본인의 현재 신청 상태(대기·승인·거절·취소)를 다시 방문해도 확인하고, 대기 신청을 취소할 수 있다. 거절·취소 결과도 기존 내 모임 목록에 남기되 대화·취소 권한은 제공하지 않는다.
- 모임장은 동의받은 프로필을 검토한 화면에서 승인·거절한다. 서버의 현재 권한·정원·차단·계정·재신청 제한이 최종 판단한다.
- 모임 상세 제목을 댓글 화면과 구분한다. 내 모임에서는 참여 중·대기를 먼저, 거절·취소 결과를 뒤에 표시한다.
- 사진 업로드·도시 선택·신청/취소·승인 후에는 진행 및 결과 피드백을 제공한다. 접근성 레이블과 큰 글자·감소된 모션을 유지한다.
- 새로운 영구 모임/회차 모델, 후기, 출석 인증, 결제, 참가자 평가는 이번 범위 밖이다.

## 구현 순서

1. 본인 신청 조회와 승인 검토 메타데이터를 기존 RLS 조회에 연결하고, 입력/공개 경계 검사를 작성한다.
2. 공유 프로필의 계정 정보, 활동 지역 선택, 미리보기, 작성 후 신청 복귀를 연결한다.
3. 상세·신청 화면에 현재 상태와 취소를 연결하고, 프로필 검토 화면에 승인·거절을 연결한다.
4. 새 컨트롤의 분석 allowlist를 등록하고 HTML 시안과 실제 웹 화면을 점검한다.

## 기존 구조와 경계

Expo 57 / React Native 0.86 / React 19.2.3 / Supabase. `src/app`은 라우트, `src/lib/chilling-data.ts`는 관련 데이터, `scripts/*.test.mjs`는 Node 기본 테스트다. 현재 계정 프로필과 `private.chilling_profiles`를 분리하고, 신청 답변은 기존 동의된 비공개 스냅샷을 유지한다. `get_chilling_application`에서 열람을 허용한 뒤에만 신청자 메타데이터를 읽는다. 신청 기록 조회는 `post_id`와 로그인한 `requester_id`를 함께 제한한다.

DB 행/함수 변경 없이 `meetup_requests` SELECT와 기존 `leave_meetup` / `respond_meetup_request`를 재사용한다. 정확한 위치나 개인 계정 정보의 공개 범위는 늘리지 않는다. 모든 콘텐츠의 서버 안전 분석과 권한 있는 관리자 검토는 ADR-0001대로 유지한다. 컨트롤 allowlist는 새 마이그레이션으로만 추가한다.

스타일은 현재 파일의 함수형 컴포넌트·명시적 props·`useFocusEffect(useCallback(...))`·theme 토큰을 재사용한다. 새 의존성과 단일 용도의 추상화는 추가하지 않는다.

## 완료 검증

- Node 테스트 284/284, 타입 검사, 변경 파일 ESLint 통과. 신청 상태·본인 범위, 공개 메타데이터 조회 순서, 조회 도중 취소된 호스트 스냅샷 폐기, 거절·취소 보존과 대화 차단, 현재 참여 우선 정렬을 검증했다.
- 코드 검토에서 발견한 취소 동시 조회·레거시 신청 링크·취소 성공 후 오래된 대화 버튼을 수정했고 별도 재검토에서 잔여 지적이 없었다.
- 테스트 데이터로 실제 React Native 컴포넌트를 렌더링한 임시 브라우저 환경에서 사진 업로드, 도시 저장, 입력 중인 관심사 저장, 프로필 작성 후 신청 복귀, 답변·동의 조건, 새로고침 후 대기 유지, 신청 중복 방지, 취소 결과 보존, 모임장 승인·거절, 거절 후 프로필 열람 종료, 정원 오류와 재시도, 상세 상태와 320px 폭을 확인했다.
- 원본 프로젝트의 공개 웹은 읽기 전용이다. 앱 화면 검증은 `/tmp/gling-meetup-native-preview`에 소스 사본을 만들고 웹 전용 라우트만 제외한 렌더 환경 및 `/tmp/gling-meetup-entry-fixtures.py`의 가짜 API로 수행했다. 운영 계정·운영 DB·원본 웹 경로를 변경하지 않았다. 임시 정적 렌더의 React SSR 경계 복구 메시지가 발생했으며 상호작용 검증을 막지는 않았다. iOS/Android 기기, 실제 서버 RLS 실행과 OS 사진 권한 UI는 별도 기기 검증 범위다.
- [화면 미리보기](../output/design/meetup-entry-essentials-2026-10-05.html): 확인한 화면과 상태를 전환할 수 있는 자체 포함 HTML. Orca의 기존 `Git → gling` 폴더에서 확인했다.

배포 시 새 분석 컨트롤 allowlist인 `supabase/migrations/0115_meetup_entry_analytics.sql`을 적용해야 한다. 새 모임 데이터 모델이나 권한 RPC 마이그레이션은 필요하지 않다.

# 글링 관계 슬롯과 홍보 시작 전 안내

2026-09-10. 사용자와 정리한 제품 정책이다. 이 문서 작성으로 앱·DB·결제 상품을 변경하지 않았다. 아래 확정 규칙과 제안을 구분한다.

## 확정한 관계 규칙

- 무료·플러스·프리미엄은 모임 슬롯과 1:1 슬롯을 각각 3·5·10개 가진다. 두 종류의 슬롯은 공유하지 않는다. 하루 글 작성 한도 1·2·5편과도 별개다.
- 1:1 한도는 동시에 유지하는 대화 수다. 기존의 하루 신규 대화 횟수 기준이나 친목/게시글 문의 예외로 해석하지 않는다.
- 대화와 모임 참여는 사전 동의가 필요하다. 1:1 요청은 상대가 수락해야 하고, 모임 신청은 방장이 승인해야 한다. 공개 모임도 자동 가입되지 않는다. 방장 초대는 초대받은 사람이 수락해야 한다.
- 요청 대기·거절·수락 전 취소는 슬롯을 사용하지 않으며 종료 후 쿨타임도 발생하지 않는다. 요청은 동의 확인용 소개이며 수락 전 대화를 허용하는 통로가 아니다.
- 1:1 수락 순간 양쪽의 사용 가능한 슬롯을 다시 확인하고 각각 한 자리를 동시에 사용한다. 어느 한쪽이라도 부족하면 대화 시작을 확정하지 않는다.
- 1:1이 종료되면 누가 종료했는지와 관계없이 최초 요청자의 해당 슬롯만 종료 시점부터 24시간 잠긴다. 수락자의 해당 슬롯은 즉시 반환한다. 최초 요청자는 대화 도중 바뀌지 않는다.
- 모임을 자발적으로 탈퇴한 사람은 해당 모임 슬롯이 24시간 잠긴다. 다른 구성원의 슬롯은 그 탈퇴로 잠기지 않는다.
- 나가기·차단·신고는 즉시 가능해야 한다. 잠금은 해당 슬롯의 재사용에 적용하며 계정 전체의 이용이나 안전 조치를 막지 않는다.

## 아직 정해야 할 종료 사례

- 모임 강퇴·해산·예정된 정상 종료, 계정 제재·삭제, 운영상 확인된 악용 및 시스템 오류로 종료된 관계의 슬롯 처리.
- 신고 제출만으로 쿨타임을 즉시 해제하는 예외는 합의하지 않았다.
- 요청 대기는 슬롯을 예약하지 않으므로 요청 중복·반복 전송·만료 처리가 필요하다. 이를 별도의 하루 대화 시작 한도로 바꾸지 않는다.
- 안전 분석·관리자 검토·접근 감사는 [기존 안전 운영 결정](../docs/decisions/0001-safety-monitoring-and-admin-access.md)을 그대로 따른다.

## 홍보 관련 사용자 요구

- 슬롯 부족을 이유로 홍보 상품 결제를 막지 않는다.
- 홍보할 글을 게시하거나 홍보를 시작하기 전에 슬롯 상태와 대화 수락에 미치는 영향을 알려주는 방안을 검토한다.
- 렌트·구인구직·중고거래·여행 동행 등 문의가 중요한 글과, 경험 공유·공론화 등 읽히는 것 자체가 목적인 글을 모두 고려한다.
- 기존 홍보 원칙은 무료 회원도 구매 가능, 자연 노출과 별도로 구매한 홍보 노출 수를 집계, 목표 수 도달 시 홍보 종료다. 가격과 판매 상품은 별도 확정 사항이다.

## 제안: 홍보를 시작하기 전에 현재 수락 가능한 대화 수 안내

1. 홍보 설정 화면에서 현재 수락 가능한 1:1 대화 수를 표시한다. 결제보다 앞서 정보를 제공해도 결제를 막지는 않는다. 글쓰기 화면 진입 때마다 팝업을 띄우지 않는다.
2. 홍보 시작 직전에 서버의 최신 슬롯 상태를 다시 확인한다. 슬롯은 이 확인으로 예약되지 않는다. 상태 조회 실패를 빈자리 0개나 충분한 자리로 표시하지 않는다.
3. 자리가 없으면 시작 버튼 가까이에 아래 내용을 표시한다. 계정의 잠긴 자리도 가용 수 계산에서 제외한다.

   > 지금은 새 대화를 수락할 자리가 없어요.
   > 대화 요청은 받을 수 있지만, 자리가 생긴 뒤 수락할 수 있어요. 글 게시와 홍보는 계속할 수 있어요.

4. 선택은 `그대로 홍보 시작`과 `글만 게시하고 홍보는 나중에`로 제공하는 안을 권한다. 이미 게시된 글에서는 두 번째 동작을 `홍보 나중에 하기`로 표현한다. 내 대화 상태를 확인하러 이동해도 작성 중인 글과 홍보 설정을 보존한다.
5. 나중에 홍보하기를 선택하면 구매한 미사용 홍보 수량을 보존하고, 시작하지 않은 홍보의 노출을 소진 처리하지 않는 안을 권한다. 이는 환불 또는 다른 글로의 구매 이전을 확정하는 규칙이 아니다.
6. 홍보 중 슬롯이 가득 차도 자동으로 게시글을 숨기거나 홍보를 중단하지 않는 안을 권한다. 조회가 목적인 글도 있기 때문이다. 관리 화면에서 상태를 계속 확인할 수 있도록 한다.
7. 홍보로 들어온 문의도 같은 1:1 요청·수락 규칙을 따른다. 홍보 구매로 별도 대화 슬롯을 자동 지급하거나 수락·쿨타임을 면제하지 않는다. 이미 유지 중인 대화는 새 슬롯 없이 이어갈 수 있다.

## 현재 구현과의 차이

- `src/lib/community-data.ts`의 `startDirectConversation`은 상대 수락 없이 방을 만든다.
- `supabase/migrations/0030_daily_conversation_membership.sql`은 하루 신규 1:1 횟수 기준이다. 확정한 동시 슬롯·최초 요청자 24시간 규칙은 아직 구현되지 않았다.
- `0011_meetup_notifications.sql`에는 모임 승인 절차가 있지만, 승인 시 방장과 신청자의 1:1을 생성한다. 모임 단체대화와 분리해야 한다.
- `output/design/gling-meetups-v2/index.html`의 하루 친목 대화 표시·문의 예외는 이전 시안이며 이 결정과 다르다.
- 앱 소스와 마이그레이션에서 유료 홍보 실행 경로를 확인하지 못했고, 관리자 분석의 `promotions.connected`는 `false`다. 위 홍보 안내는 연결 완료된 기능의 설명이 아니다.

## 구현 시 필요한 최소 검증

- 수락 전 접근·메시지 전송 차단, 양쪽 마지막 자리 동시 수락 경쟁, 중복 수락으로 인한 이중 사용 방지.
- 어느 쪽이 종료하든 최초 요청자만 24시간 잠금, 수락자 즉시 반환, 대기 요청 취소는 잠금 없음.
- 0개와 잠긴 자리 표시, 확인 후 상태 변경, 조회 실패 처리, 기존 대화 이어가기.
- 0개여도 결제·게시·사용자가 선택한 홍보 시작 가능, 나중에 시작 선택 시 글과 미사용 수량 보존, 자연 노출은 구매 수량에서 미차감.

## 디자인 참고 범위

기존 Apple 디자인 스킬의 동작 가까이에서 상태를 알리고 사용자의 선택을 유지하는 원칙을 적용했다. 이번 Mobbin 홍보 검토 화면 검색은 결과가 없었고, Pinterest 검색은 일반 경고 컴포넌트 중심이라 특정 서비스의 홍보 정책 근거로 채택하지 않았다. 기존 Gling B 컨셉을 바꾸는 제안은 포함하지 않는다.

## 구현 진행 — 새 출시 빌드

이 문서 상단의 구현 전 차이는 조사 당시 기록이다. 현재 `0033_relationship_slots.sql`과 앱 요청함/대화/모임 UI로 위 규칙을 구현했으며, 빌드 8에 포함했다. 실제 배포와 검증 결과는 [출시 기록](relationship-release-2026-09-10.md)을 따른다. 기존 직접 대화는 당시 최초 요청자 기록이 없어 NULL로 보존한다. 기존 방이 끝날 때는 소급 잠금을 부과하지 않고, 새로 요청/수락한 관계부터 최초 요청자 책임을 적용한다.

모임장 자발적 해산은 모임장만 24시간 잠금, 수동 참여자 자리는 즉시 반환한다. 계정 제재·운영상 종료는 관계를 닫되 상대방에게 잠금을 부과하지 않는다. 기존 데이터 삭제/보존 정책과 신고/안전/감사 경로를 유지하고 그룹 메시지로 확장한다. 새로운 초대 기능은 현재 없으며 공개 검색→신청→승인 경로만 제공한다.

수락은 서버의 공통 관계 변경 잠금으로 직렬화한다. 초기 규모에서는 최소 구현이며, 경합이 관측되면 정렬한 회원별 잠금으로 교체한다. 대화 요청은 7일 만료, 발신 대기 20개, 시간당 20회·30초 간격의 스팸 제한을 적용한다. 거절·취소한 동일 쌍은 24시간 뒤 다시 요청할 수 있다. 대기 요청에는 사용/잠금 슬롯을 추가하지 않는다.

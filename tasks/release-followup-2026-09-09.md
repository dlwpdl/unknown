# 글링 화면·심사 계정·광고 등록 — 2026-09-09

## 앱 변경

- 공통 글자 크기와 글 카드 여백을 줄였다. 이 날짜의 시각 방향은 현재 나이트 브랜드 기준이 아니다.
- 하단 메뉴는 오늘·모임·글쓰기·채팅·알림, 프로필은 상단 검색 오른쪽이다. 웹은 개별 버튼 배경을 없앤 한 개의 바, iOS는 운영체제의 기본 탭 바를 사용한다.
- 모임 탭은 현재 기존 모임 게시글과 참여 신청 흐름을 재사용한다. 가입 모임·공개 모임과 공통 그룹 채팅의 새 구조는 별도의 디자인 검토 단계다. 현재 승인 흐름은 주최자와의 1:1 대화를 연다.
- 좋아요·댓글·저장·공유·조회수를 왼쪽에 8pt 간격으로 모았다. 조회수는 비활성 정보로 한 번만 표시한다.
- 기존 DB의 `(post_id, user_id)` 기본키와 충돌 무시 처리가 같은 계정의 중복 조회를 막는다. 클라이언트의 세션별 임의 `+1`과 메모리 캐시를 삭제하고, 공통 상세 화면에서 서버 집계를 읽는다. 검색·저장 목록에서도 같은 처리를 사용한다.
- 위로 스크롤하면 짧은 동작으로 상단 메뉴가 돌아온다. React Native의 기본 sticky header를 사용하며 Reduce Motion에서는 헤더를 고정한다. iOS 26.5 실행 화면에서 아래로 읽을 때 숨김과 목록 중간에서 위로 돌아올 때 재등장을 확인했다.
- 도시 선택은 준비 중인 도시에만 상태를 표시한다. 선택된 준비 중 도시에도 배지는 남는다.
- iOS `CFBundleName`을 `글링`으로 지정했다. 로그인 시스템 팝업의 서비스 도메인은 소유 도메인과 인증 서버 구성이 마련되어야 교체할 수 있다. 현재 Supabase 호스트는 유지한다.

## 심사용 접근과 데이터

- 공개 이메일 가입과 승인되지 않은 비밀번호 로그인은 서버에서 거부한다. 심사 계정은 관리자가 설정한 `app_metadata.review_access`로만 허용하며 일반 L1 권한이다. Kakao/Apple 및 기존 관리자 인증을 보존한다.
- 로그인 진입: 상단 검색 오른쪽 사람 아이콘 → `심사용 계정 로그인 / Review access`. 현재 자격 증명과 안내를 App Store Connect와 Google Play에 저장하고 재조회했다. 개인 비밀번호·토큰은 저장소에 없다.
- 루트 Stack을 고정하여 심사 로그인 뒤 프로필로 돌아오지 못하던 웹 경로를 수정했다. 잘못된 비밀번호 거부, 로그인 → 프로필 → 알림 → 뒤로, 세션 재실행을 브라우저에서 확인했다.
- 마이그레이션 0023, 0024, 0025는 운영 프로젝트에 적용됐다. 시드 53개 게시글·37개 작성자의 표시용 `예시` 표기만 정리했고, 일반 사용자 콘텐츠·집계·인증 등급은 바꾸지 않았다. 원래 시드 데이터는 실제 이용자 활동의 증거가 아니다.
- [ADR 0001](../docs/decisions/0001-safety-monitoring-and-admin-access.md)의 전체 콘텐츠 안전 모니터링·동의·관리자 감사 범위를 유지한다.

## 검증

- `npm test`: 42개 통과. 타입 검사와 lint 통과.
- 배포 도구에 포함된 `js-yaml`의 [보안 패치](https://github.com/advisories/GHSA-2883-xcg3-v3hh)를 4.3.1 → 4.3.2로 적용했다. 직접 의존성을 추가하지 않았으며 lockfile만 변경했다. 재검사에서 high/critical 0, 기존 moderate 14건이다. 앱 런타임에는 YAML 처리를 사용하지 않는다. 패치 후 lint가 통과했다.
- `node scripts/check-feed-navigation.mjs <GLING_PAGE_ID>`: 다섯 목적지, 검색 옆 프로필, 왼쪽 반응 그룹과 한 번만 나오는 조회수, 320~1440px 가로 넘침 없음.
- `node scripts/check-review-navigation.mjs <GLING_PAGE_ID>`: 잘못된 비밀번호와 정상 심사 로그인, 알림 왕복 및 세션 복원 통과.
- 심사용 접근 DB 검사 14개와 조회수 DB 검사 3개를 트랜잭션 안에서 실행했다. 재열기는 1회, 다른 계정은 별도로 집계됨을 확인했고 검사 데이터는 롤백했다.
- 도시 선택의 `운영 중` 제거와 `준비 중`·선택 상태 보존을 브라우저에서 확인했다.
- 실제 개인 Kakao/Apple 인증 완료와 테스트 계정의 소셜 연결 해제·탈퇴는 이 자동 검사 결과에 포함하지 않는다.

## 배포 상태

- iOS/Android `1.0.0 (6)` Release 빌드를 생성하고 서명을 확인했다. 원본은 `~/Library/Application Support/gling/releases/1.0.0-6/`에 보관한다.
- App Store Connect: 빌드 6 처리가 끝나 기존 1.0.0 버전에 연결됐다. 한국어 What to Test를 저장했고 제출 점검은 오류·경고 0이다. 수동 출시의 `PREPARE_FOR_SUBMISSION` 상태다.
- Google Play: `1.0.0 (6)`이 활성 내부 테스트 버전이며 지정된 내부 테스터에게 제공된다. 지원 기기 감소는 없고, 난독화를 사용하지 않아 ReTrace 매핑 파일 미첨부 경고만 남았다.
- App Store 화면 3장과 Play 휴대전화 화면 4장을 빌드 6의 실제 화면으로 교체하고 재조회했다. 웹 소개 화면도 같은 iOS 이미지를 사용하며 `/gling` 경로의 정적 내보내기가 통과했다.
- iPhone X(iOS 16.7.14)에 빌드 6 설치가 완료됐다. 마지막 캡처는 잠긴 화면이므로 사용자가 잠금을 푼 뒤 실행 확인이 필요하다.
- iPhone 16 Pro Max / iOS 26.5와 Android API 36에서 실제 빌드 6의 밴쿠버·토론토 피드 전환 및 도시 상태 표시를 확인했다. 기존 iOS 18.4 시뮬레이터에서는 CFNetwork 연결 오류가 발생했으며, 새 iOS 26.5 환경의 동일 빌드에서는 정상이다.
- 공개 심사와 프로덕션 출시는 아직 하지 않았다. 웹은 `mobile-app` 브랜치의 GitHub Pages 배포를 사용한다. 문제 발생 시 이번 UI 커밋을 되돌려 Pages를 재배포하고, 스토어는 검증된 이전 빌드로 초안을 되돌릴 수 있다. 심사용 인증 제한과 데이터 마이그레이션은 UI 롤백과 분리해 유지한다.
- UI·출시 준비 커밋 `94d0fbd`를 `dlwpdl/gling`에 푸시했고 GitHub Pages 배포가 성공했다. 공개 홈페이지의 새 iOS 화면 3장이 모두 로드되는 것을 확인했다.

기존 출시 준비를 반영한 뒤 [콜하버 실사진 글 한 편](vancouver-photo-2026-09-09.md)을 추가했다. 게스트의 공개 글 사진 접근 문제도 DB 정책에서 수정했다. 실제 게시글 공유용 웹 페이지는 기본 Supabase 도메인의 `text/plain` 응답 문제가 있어 도메인·제공 경로 정리가 남았다.

## 모임·채팅 디자인 제안

[클릭 가능한 시안](../output/design/gling-meetup-chat-flow.html)은 모임의 `내 모임 / 둘러보기`와 채팅의 `전체 / 모임 / 개인`을 제안한다. 양쪽에서 같은 대화방을 열고 뒤로 가면 출발한 탭으로 돌아온다. 가입 대기 상태에서는 대화를 열 수 없으며, 읽음 상태와 메시지는 하나로 공유한다. 320px·375px·데스크톱에서 넘침과 버튼 크기를 확인했고 양쪽 진입·읽음·뒤로 가기 흐름을 브라우저에서 검증했다. 실제 그룹 채팅 구현은 포함하지 않는다.

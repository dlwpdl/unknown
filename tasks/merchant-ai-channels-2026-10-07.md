# 소상공인 AI 초안·게시 선택

사용자 승인: 2026-10-07 대화의 시안 확인 → “좋다” → “진행시켜”. 기존 Expo 앱의 소상공인 도구에 연결한다.

## 목표와 기준

- 이번 소식 한두 문장을 입력해야 AI 초안을 요청할 수 있다. 공백만 입력하면 클라이언트와 서버 모두 거절한다.
- 기존 `draft-post`의 인증·AI 동의·하루 5회 한도를 재사용한다. 서버의 업체 접근 권한 확인 뒤 가게 이름·도시만 문맥으로 전달한다. 연락처·재고·관리자 메모는 전달하지 않는다.
- 가게 소식 / 메뉴·서비스 소개 / 구인구직 목적에 맞춘 원고를 만들고, 가격·날짜·주소·방문 경험을 지어내지 않는다. 사용자 후속 지시: 가게를 대표하는 공손하고 친근한 존댓말을 사용한다. 일반 회원·사진·행사 모임의 기존 작성 지침은 유지한다.
- 생성 결과는 직접 수정한다. 오류·취소·계정 전환 시 이전 원고를 덮어쓰지 않는다. 기존 승인·최신 저장본 검사를 재사용한다.
- 새 원고는 글링 ON, 네이버·다음 OFF. 선택한 곳과 원고를 확인한 뒤 글링만 실제 게시한다. 카페는 자동 연결이 준비되기 전까지 원고 복사·직접 등록으로 표시한다.
- 초안 저장은 게시와 별개다. 게시 성공 후 같은 원고를 재게시하지 않는다. 기존 캐스모·헬로밴쿠버 저장 원고의 편집·복사·URL 기록은 유지한다.

## 구조와 스타일

`supabase/functions/draft-post/index.ts`: 소상공인 intent와 서버 문맥. `src/components/merchant-workspace.tsx`: 기존 편집기·폼·피드백·실행 잠금·원고 승인/게시 RPC를 재사용한다. 새 의존성·DB 변경·예약 자동화는 필요 없다.

현재 night/iris 테마, 시스템 글꼴, 44px 조작 영역, React Native Switch와 기존 `useInteractionFeedback().play(...)`를 사용한다. 단계마다 주 행동 하나, 사실 입력 → 편집 → 게시 채널 확인. 확인 단계에서는 원고 목록을 접는다. 게시한 글을 다시 열어도 카페 원고를 준비할 수 있다.

서버 업체 확인은 `get_merchant_workspace(p_merchant_id)`의 기존 소유자·활성 계정·관리자 AAL2/감사 검사를 재사용한다. 50개 제한이 있는 업체 목록으로 권한을 판정하지 않는다. 응답에서 가게 이름·도시만 AI에 전달한다.

근거: Apple Design 스킬, [Buffer AI 입력·삽입](https://mobbin.com/screens/ff1e037e-1a9f-4bd3-8264-45189fe6ec0e), 승인된 `output/design/gling-merchant-ai-channels-2026-10-07.html`, 공식 Expo SDK57 문서.

## 업체 관리 화면 개편 · 2026-10-07

후속 지시: 업체 관리 화면 전체를 Apple Design과 Mobbin의 실제 사례를 참고해 다시 설계한다. 긴 설명과 입력 폼을 첫 화면에서 분리하고 기존 도구의 기능·승인·접근 권한은 유지한다.

- 업체 요약에서 홍보글 작성 하나를 주 행동으로 두고, 홍보글 관리·원가 계산·재고 관리·성과/이용 상태를 그룹 메뉴로 연결한다. 한 업체만 있으면 바로 열고, 업체 선택을 닫아도 작성 중인 초안을 유지한다.
- 원고 목록과 작성 화면을 나눈다. 뒤로가기·이어쓰기는 편집 상태를 유지하며, 다른 업체나 새 등록으로 전환할 때 기존 초안 폐기 확인을 유지한다. 등록 화면에서 취소하고 기존 업체로 돌아갈 수 있다.
- 원가 입력과 결과는 두 열로 정돈한다. 재고는 목록부터 보여주고 품목 추가/수정 폼과 입출고 기록을 분리한다. 성과는 주요 수치를 먼저 보여주고 상세 기준과 이용 범위는 접는다. 업체 요금 준비 중·자동 결제 없음과 클릭의 측정 한계는 계속 표시한다.
- 기존 night/iris 브랜드, 네이티브 SymbolView, 44px 조작 영역과 모든 조작의 즉시 시각/상호작용 피드백을 사용한다. 새 의존성·데이터 모델·연동 서비스는 추가하지 않는다.

실제 확인한 근거: [Shopify 업체 요약](https://mobbin.com/screens/635cf029-446c-4cdb-a3aa-bb1278e8291e)의 작업 중심 진입점과 [Apple Fitness 계정 메뉴](https://mobbin.com/screens/f618bfa8-e996-4cb6-b7b8-f138e29963b1)의 그룹 행 구조. Apple Design의 친숙한 탐색·절제된 위계·즉시 반응을 적용했다. Kroma는 API 키 부재로 조사하지 못했으며 참고 근거에 포함하지 않는다.

클릭 가능한 로컬 시안: `output/design/gling-merchant-workspace-redesign-2026-10-07.html`. 실제 앱 컴포넌트에 모의 계정·서버·AI를 연결하며, 외부 게시·결제는 실행하지 않는다. 공통 디자인 작업 지침에도 사용자의 재언급 없이 Apple Design과 Mobbin을 먼저 적용하도록 재확인했다.

## 순서와 검증

1. 서버 테스트부터 작성: 빈 내용·접근 거절은 AI/한도를 사용하지 않으며, 서버 업체 문맥만 전달한다. 소상공인 지침과 기존 intent의 분리를 확인한 뒤 서버 구현.
2. 기존 편집기에 목적·필수 설명·AI·채널 스위치·최종 확인을 연결. 제목/본문 저장·승인·게시 revision을 유지.

# Gling share preview gateway

`share-preview-worker.ts` is a dependency-free `fetch` handler for a configured Gling gateway's `/share/:UUID` and `/s/:compactUUID` routes; it also supports the original app origin when no separate gateway is configured. **The dedicated Node 22 gateway is deployed at https://gling-share-preview.vercel.app. On 2026-10-13, an actual public post returned HTTP 200 HTML with matching title, canonical URL, primary-site CTA and a working Supabase cover.** That historical readback covers the UUID route. On 2026-10-17, the compact route and primary-site redirect were also deployed: both URLs returned HTTP 200 for the same public post, with matching title, fixed primary-site CTA and a working cover. [PR 45](https://github.com/dlwpdl/unknown/pull/45) changed only `public/share-redirect.js` on the primary site; [Pages run 39090638422](https://github.com/dlwpdl/unknown/actions/runs/39090638422) succeeded, and the served script matched the approved source. GitHub Pages serves static app files and cannot generate per-link metadata. Supabase Edge Functions currently serve HTML as `text/plain`, so pointing a share URL at that function is not a working OG deployment.

Keep `https://gling.ej-entertainment.com` as the website and authentication origin. A separate fixed Gling-owned Vercel project origin may serve `/share/:UUID` previews without moving the website or changing its DNS. The release owner must confirm the actual stable gateway alias before activating generated gateway links. Local preparation creates no account, DNS change, schedule, paid service, deployment, or production credential.

The worker bindings are:

| Binding | Value |
| --- | --- |
| `APP_URL` | `https://gling.ej-entertainment.com` — the fixed website/login origin, without a path/query/fragment |
| `SHARE_ORIGIN` | Optional configured HTTPS gateway origin for canonical and OG URL metadata only; defaults to `APP_URL` |
| `SUPABASE_URL` | The existing project's HTTPS origin |
| `SUPABASE_PUBLISHABLE_KEY` | The existing `sb_publishable_…` key or legacy `anon` JWT; never a secret or service-role key |

The only data read is `POST /rest/v1/rpc/get_shared_link_preview` with `{ "p_post_id": "UUID" }`. Its result is `null` for unavailable links, or `{ id, title, kind, city, label, schedule, imagePath, closed }`, where `kind` is `post`, `festival`, or `meetup` and `schedule` is `null` or `{ eventKind, startsAt, endsAt, timezone, cadence }`. Recurring `group` cards show cadence; one-off cards show their date in the supplied timezone. The RPC must enforce the source post and account's visibility/moderation rules and exclude hidden/deleted content. It must never return body text, comments, review authors, or precise meeting places. The worker only renders these preview fields and discards any extra fields; it does not bypass source filtering or mint invitation authority.

If `imagePath` is present, the worker attempts to sign that exact path in the fixed `post-images` bucket with the same publishable key, a one-day expiry, and no redirects. A denied or invalid image falls back to the source-owned 1200×630 covers `public/share-covers/post.png`, `festival.png`, and `meetup.png` (stories from Vancouver, Toronto or Montréal use `vancouver.png`, `toronto.png` or `montreal.png`); the web export must retain those files at `/share-covers/<name>.png`. They are typographic Gling covers rendered by `scripts/render-share-covers.py` from the brand wordmark and the existing meetup/festival 3D art, not generated illustrations. Titles and covers are intentionally visible to link recipients and platform preview caches; body text stays absent from the HTML.

The original HTML contains escaped Open Graph and Twitter large-image tags before any JavaScript. Crawlers and people receive the same preview. `public/share-redirect.js`, served at the fixed app origin's `/share-redirect.js`, immediately continues to the fixed primary CTA destination using `location.replace`. It allows only `https://gling.ej-entertainment.com/post?id=UUID&shared=1`, with optional `&invite=1`, and requires the UUID to match the current `/share/:UUID`, including when that page is hosted on the configured gateway. It rejects gateway-hosted login destinations, lookalike origins, credentials, extra query keys and ambiguous UUID parameters. A visible CTA remains usable with JavaScript disabled. There is no user-agent discrimination or inline script; CSP permits scripts only from the fixed app origin. The app must open authentication before returning the body and retain that destination through Google/social login. Possessing a link alone never grants membership or permits an outsider to bypass application or host approval.

`SHARE_ORIGIN` is validated with the same HTTPS-origin rules as `APP_URL` and affects only canonical/OG URL metadata. CTA/login destinations, fallback covers, redirect-script source and CSP remain fixed to `APP_URL`; neither an incoming Host nor caller query parameters can supply either configured origin.

Responses use `no-store`, a restrictive CSP, and generic 404/405/503 errors. Fetches are bounded to five seconds each and only use the configured Supabase origin. Query parameters, incoming Host, caller cookies, and caller authorization cannot change a backend URL, destination, kind, or account. Signed images can expire in a third party's cached preview; refreshing that platform's preview is separate from a new worker response.

## Vercel prebuilt bundle

Run `node infra/build-vercel-output.mjs` after the existing public and merchant export. It copies `dist` unchanged to `.vercel/output/static` and compiles the share handler, shared UUID codec, Web adapter and small Node HTTP adapter with the installed TypeScript compiler and Node types. The function manifest uses `runtime: nodejs22.x`, `handler: infra/node-share-preview.js` and `launcherType: Nodejs`; its local package declares ES modules. The generated `.vercel/output` stays ignored. Preparation does not deploy anything.

The adapter uses the bindings above as Vercel runtime environment variables. Keep `APP_URL=https://gling.ej-entertainment.com` and `SHARE_ORIGIN=https://gling-share-preview.vercel.app`. The stable alias belongs to the dedicated `gling-share-preview` project in the existing LaneHelm account; production deployment `dpl_FC12c1aYQjCAENdi4fDK8WDoEiHc` was verified by live HTTP requests. Deployment uses the existing authorized Vercel CLI with `deploy --prebuilt`; no CNAME or primary-site migration is required. Gateway `/auth/*` and `/merchant/auth/*` routes return 404. Copied static callback files do not establish a supported login flow there; authentication continues on the primary website.

The Node adapter supplies only the path and GET/HEAD method to the shared handler, using a fixed gateway origin. Other methods are normalized to POST so the existing handler returns 405, including methods the Web Request constructor would reject. Caller Host, cookies, authorization and body are never forwarded. Existing response headers/status and the small HTML body are copied to the native response; HEAD remains empty.

Both share routes capture their identifier into `__gling_share_id`. The compact identifier is the entire 16-byte UUID encoded as 22 canonical base64url characters; it is not an access token or a truncated identifier. Caller query collisions and direct access to the internal function route return 404. The adapter preserves an original share request; if Vercel supplies the rewritten internal URL, it reconstructs only a validated UUID or compact identifier before calling the preview handler. Static files are checked first after the share routes, followed by existing HTML/index routes and the exported 404.

Confirm both old and compact links show matching metadata and continue only to the original site's matching post. The default generated URL shrinks from 81 to 63 characters. ## Gateway 503 diagnostics

The on-call question is which validation or I/O stage produced the 503. The existing Vercel request log supplies correlation. A structured `share_preview_unavailable` event includes a fixed `stage`, a numeric HTTP `status` for `UPSTREAM_STATUS`, and a fixed `error_kind` for `PREVIEW_FETCH`. The kind is `TIMEOUT` when the request signal aborted or the exception has a timeout/abort name, `NETWORK` for a fetch TypeError, and `OTHER` otherwise. These broad categories do not identify a particular socket, redirect or platform-binding cause. It excludes URLs, post IDs, titles, payloads, keys, caller headers, exception messages and stack traces. Public error responses remain generic.

`APP_ORIGIN`, `SHARE_ORIGIN`, `SUPABASE_ORIGIN` and `PUBLISHABLE_KEY` identify configuration validation. `PREVIEW_TIMEOUT` identifies timeout-signal creation; `PREVIEW_FETCH` identifies the outbound request; `UPSTREAM_STATUS` records a remote refusal; `PREVIEW_JSON`, `PREVIEW_SCHEMA` and `PREVIEW_HTML` identify parsing, contract validation and rendering. Check the dedicated project's existing Vercel logs with `--deployment <deployment-id> --status-code 503 --since 30m --json`. Change the failing stage only after inspecting its evidence.

Read-only probes on 2026-10-13 used the actual configured publishable key and missing-post UUID with verified TLS, `redirect: error` and the original five-second timeout. Node global fetch and cached EdgeVM global/unbound fetch each returned HTTP 200 with the expected null preview. The deployed Edge function logged `PREVIEW_FETCH` with `NETWORK` in about half a second; the specific transport cause was not reproduced locally. The documented Node 22 adapter resolved the live failure without changing TLS, redirects, timeouts, public-key-only access or the public response boundary. The successful production checks are recorded in the release handoff receipt.

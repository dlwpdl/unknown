# 비즈니스 웹 진입과 AI 연결

사용자 승인: 일반 회원의 작성·모임 참여·대화는 앱, 비즈니스 운영은 앱·웹·MCP로 제공한다. 공유된 공개 글은 기존처럼 웹 로그인 후 읽을 수 있다.

- 같은 글링 계정을 사용한다. 클라이언트의 가입 선택이나 프로필 문구로 권한을 부여하지 않는다.
- 기존 서버의 비즈니스 승인과 담당 목록을 조회해 일반 회원 / 승인 후 미연결 / 연결된 운영자로 구분한다. 관리자 전체 조회 행은 운영 비즈니스로 취급하지 않는다.
- 운영 담당자는 배정된 비즈니스만 웹에서 관리한다. AI 신규 연결은 소유자 역할·현재 계정의 소유·소유 확인이 모두 있는 경우에만 안내한다.
- 기존 승인된 계정의 비즈니스 등록과 초대 수락은 보존한다. 연결·등록 후 권한을 다시 조회한다.
- 권한 상실 후에도 기존 AI 연결 조회·해제는 유지한다. 서버의 매 호출 소유권·동의·세션 검사와 원고 승인 절차는 그대로 사용한다.
- 공개 웹에는 비즈니스 관리 진입을 제공한다. 공개 글을 읽다가 로그인한 오너를 강제 이동시키지 않는다. AI 화면 로그인은 같은 화면으로 복귀한다.
- 웹 모임 참여 경로는 앱 안내로 연결한다. 이는 배포된 웹 기능의 경계이며 일반 인증 토큰이 네이티브 기기임을 증명하는 보안 경계는 아니다.
- 2026-10-25 사용자 정정: 웹 메인은 앱의 오늘처럼 글 피드가 먼저 보인다. 모임 소개 히어로와 홈 전용 모임 목록/추가 조회를 제거하고, 상단 Meetups 메뉴에서 같은 도시의 커버 사진 중심 공개 모임 목록을 제공한다. 모임 카드 전체는 같은 글의 로그인·가입 안내(`/post?id=…&invite=1`)로 연결하고 실제 참여는 앱에서 이어간다. 일정·도시·실제 참여 인원·모집 상태를 유지한다. 참가 신청·개인 프로필·대화는 앱으로 이어간다.
- 스토어를 직접 선택한 뒤 해당 QR을 표시한다. 설치 후 원래 페이지로 돌아와 앱에서 여는 동선을 안내하며 자동 설치 후 목적지 복원을 약속하지 않는다. 종료·마감된 모임은 참여 대신 앱에서 보기로 연결한다.

기존 API와 디자인·피드백을 재사용한다. 새 DB 역할·인증 서비스·의존성·스토어 배포는 추가하지 않는다. 행동 검사, 타입·린트·웹 export, 격리한 화면 QA로 검증하며 실제 외부 AI OAuth 연결·운영 게시와 구분한다.

- 상단 로그인은 같은 계정의 비즈니스 관리 진입을 재사용한다. 일반 회원은 친근한 앱 참여 안내와 스토어 선택·QR을 바로 보고, 소유자·운영자는 서버에서 배정된 비즈니스 화면을 본다. 공개 글 로그인 후 웹 열람과 AI 화면의 명시적 복귀 동작은 보존한다. 일반 로그인 시작 때 취소한 AI 전용 복귀 마커만 제거한다.

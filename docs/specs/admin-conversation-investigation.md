# 대화 단위 조사함

2026-10-12 사용자가 HTML 시안을 확인하고 “시안대로 진행해”라고 승인했다. 기준 소스는 공유·초대 버튼이 병합된 `7723667bd675ad804b59ed052803fe61fd54e637`이다.

## 목적과 완료 조건

도시 → 대화 상대 → 전체 대화로 좁히면서 목록과 검토 기록을 함께 본다. 기존 관리자 밝은 테마와 승인된 배치를 유지한다. 좁은 화면에서는 목록, 대화, 조사 기록을 차례로 연다.

- 메시지를 대화방 단위로 묶고, 두 참여자 또는 그룹 참여자와 등록 도시를 표시한다. 서로 다른 도시의 대화는 양쪽 도시에서 찾을 수 있다. 미등록 도시와 종료된 대화도 제외하지 않는다.
- 서버가 도시·종류·기간·위험 수준·검색·검토 상태를 적용하고 대화 단위로 페이지를 반환한다. 처음 불러온 메시지 50개를 전체 결과로 취급하지 않는다.
- 감시어 경보와 AI 분석 신호를 함께 보여준다. 분석 대기는 위반 신호나 안전 확정으로 표시하지 않는다. 전체 대화에는 감지 신호가 없는 대화도 포함된다.
- 대화를 열 때 선택한 방의 메시지만 페이지별로 읽는다. 신호를 누르면 해당 메시지 앞뒤 문맥을 바로 조회한다. 원본이 없어도 보존된 경보 문구는 표시한다.
- 참여자 버튼은 기존 회원 조사 화면을 연다. 검토 상태와 메모는 실제 서버에 저장하고, 기존 기록은 남긴다. 이 저장은 경고·계정 제한·대화 전송을 실행하지 않는다.
- 검토 완료 후 새 위험 신호가 생기면 다시 검토 필요로 표시한다. 다른 운영자의 저장 또는 새 신호가 발생한 뒤 오래된 화면에서 저장하면 충돌을 알리고 입력한 메모를 보존한다.
- 모든 조회와 저장은 기존 `private.is_admin()`의 MFA·활성 세션 경계를 통과하고 대화 ID를 기존 접근 로그에 남긴다. 익명과 일반 회원은 읽거나 쓸 수 없다.

## 구현 범위

`src/lib/admin-conversations.ts`는 필터와 RPC 계약을 담당한다. 관리자 컴포넌트는 설치된 React Native의 View·Pressable·FlatList·Modal을 사용해 웹과 네이티브가 같은 조회 및 저장 경로를 쓴다. 기존 `useInteractionFeedback().play(...)`를 모든 새 컨트롤에 연결한다.

기존 메시지별 감시·AI 큐·회원 조사·접근 감사 로그를 재사용한다. 대화별 메모에는 메시지 신고에 종속된 `moderation_actions`를 사용하지 않고, append 방식의 별도 검토 기록을 추가한다. 서버 함수와 필요한 인덱스는 이 기능의 migration 하나로 관리한다. 원본 메시지나 기존 경보 상태는 수정하지 않는다.

운영 검증에서 메시지의 `reply_to_id`가 테스트 DB에만 존재하는 것을 확인했다. 이미 적용한 조사 migration은 보존하고, 별도 호환 migration에서 선택적인 답장 정보를 JSON으로 읽도록 수정한다. 이 필드가 없는 DB에서도 원문을 읽을 수 있으며, 메시지 테이블과 기존 함수 권한은 바꾸지 않는다.

기존 관리자 호스팅은 로컬 `scripts/serve-admin.py`의 `.admin-dist`, 127.0.0.1:54321이다. 관리자 export는 공용 Pages 빌드와 분리돼 있으며 CI에서 금지된다. 검증한 관리자 bundle만 기존 호스팅에 반영하고 이전 bundle과 복구 경로를 보관한다. 네이티브 태그·빌드·스토어 제출은 이 작업 범위에 포함되지 않는다.

## 검사 명령

```sh
node --experimental-strip-types --test scripts/admin-conversations.test.mjs
npm test
npx tsc --noEmit
npm run lint
python3 scripts/check-admin-conversations.py
GLING_LOCAL_ADMIN=1 npx expo export --platform web --output-dir .admin-dist
```

SQL 검사는 기존 `supabase_db_gling`에서 트랜잭션으로 실행하고 rollback한다. 익명·일반 회원·AAL1·AAL2, 도시 양쪽 일치, 그룹·미등록, 메시지 페이지 경계, 오래된 신호 앞뒤 조회, 메모 검증, 저장 충돌과 새 신호 재개를 검사한다. 실제 React 화면은 모의 데이터로 도시·검색·필터·열람·메모 저장과 좁은 화면 이동을 확인한다. 운영 검증은 필요한 경로와 권한·정의·bundle readback을 확인하고 실사용 메시지를 공개 QA 자료에 복사하지 않는다.

## 경계

항상: 저장 실패 시 초안 보존, 원본·이전 검토 기록 보존, 서버 권한 검사, 페이지 제한과 입력 검증, 승인된 시안과 기존 관리자 테마 준수.

허용된 변경: 승인한 조사함에 필요한 클라이언트, additive migration, 관련 검사, 기존 관리자 bundle 반영. 새 의존성·자동화·계정·DNS·법 집행 연락·실사용자 경고/차단·새 네이티브 제출은 추가하지 않는다.

# 글링 전체 성과 분석

사용자가 활동·재방문·참여·행사/장소·알림·유입·수익·품질 추천을 확인하고 2026-10-14 구현을 승인했다. 기존 비공개 관리자 분석과 Supabase 기록을 확장하며 새 분석 서비스나 SDK는 추가하지 않는다.

## 성공 기준

- 실제 로그인 회원의 UTC 기준 DAU/WAU/MAU, 방문 빈도, 기간별 추이와 D1/D7/D30 가입 코호트를 보여준다. 아직 관측 기간이 끝나지 않았거나 원자료 수집 전인 구간은 확정 0%로 표현하지 않는다.
- 가입·온보딩 단계, 추적 가능한 유입, 글/댓글/모임/상호 대화, 행사/장소 행동, 알림, 결제·구독, 오류·신고 처리의 8영역을 기존 관리자 안에서 조회한다. 각 항목은 실제 저장한 기록과 수집 시작/보존 범위 및 미수집을 명시한다.
- 관리자·목·심사·테스트는 기본 제외한다. 데이터가 없는 상태와 요청 실패를 구분하고 기간(7/30/90일)·도시·플랫폼 필터의 적용 범위를 설명한다. 현재 멤버십/선호 도시와 행동 당시의 도시를 혼동하지 않는다.
- 푸시 탭과 인앱 알림 항목 탭을 별도로 기록한다. 목록을 읽는 기존 일괄 읽음 처리는 클릭 집계에 포함하지 않는다. 같은 알림/입구 재전송은 중복되지 않으며 계정 소유권·접근 가능성·플랫폼과 서버 시각을 검증한다.
- Expo/APNs/FCM 접수와 실제 단말 표시를 구분한다. 현재 푸시 큐 7일 보존 범위 바깥의 발송 성공을 추정하지 않는다. 동일 수신자의 여러 기기로 클릭률을 부풀리지 않는다.
- 행사·장소 클릭/열람/외부 이동 기록은 실제 대상과 행동에 연결한다. 이름/주소/검색어/본문/사진/좌표/전체 URL을 분석 원자료로 보내지 않는다. 공식 대상 ID와 고정된 행동·유입 코드만 사용한다. 길찾기 클릭을 실제 방문으로, 공유창 열기를 공유 완료로 집계하지 않는다.
- 수익은 확인된 일반 멤버십의 실제 서버 결제 이벤트를 운영/테스트와 상품군으로 분리하고, 통화별 발생액·갱신·해지·환불 확인 범위로 표시한다. 업체 상품이 일반 가입 유료 전환으로 섞이지 않게 한다. 총 결제와 스토어 정산액을 구분하고 환불/정산·유료 홍보/광고는 미연결로 남긴다.
- 오류는 기존 클라이언트 오류 기록을 활용하고 앱 버전/플랫폼별 집계만 노출한다. 분석 화면에 대화·오류 원문이나 개인 연락처를 포함하지 않는다. 신고/안전 검토 범위와 관리자 MFA/감사·탈퇴 삭제는 유지한다.
- 추가 클라이언트 기록은 새로운 앱 코드부터 수집된다. 이미 심사 대기인 1.2.3(65) 바이너리나 기존 태그를 바꾸거나 중복 제출하지 않는다. 과거 클릭/유입을 만들어 백필하지 않는다.

## 기존 구조와 스타일

Expo SDK57, React Native0.86, React19, TypeScript6, Supabase PostgreSQL. 기존 src/components/admin/admin-analytics.tsx의 필터/탭/표와 Colors.admin/Spacing를 재사용한다. 공개/업체 빌드에서 관리자 코드를 제외하는 기존 경계를 유지한다. 서버 집계는 MFA를 요구하는 private.is_admin()과 public.log_admin_access('analytics') 이후에만 반환한다. 신규 원자료는 private 스키마, 제한된 RPC, 서버 시각, 계정 삭제 cascade와 기존 보존 작업을 재사용한다.

```ts
const result = await client.rpc('get_admin_performance', { p_days: filters.days, p_city: filters.city, p_tier: filters.tier, p_include_internal: filters.includeInternal });
if (result.error) throw result.error;
```

## 구현 순서·소유권

1. 감독자: 실제 소스/운영 메타데이터와 기존 집계·권한·보존 기준 대조. 하위 담당자는 .release/performance-data-map.md만 작성한다.
2. 디자인 담당자: 새로운 output/design/gling-admin-performance-20261014/만 소유하며 실제 참고 화면에 근거한 HTML과 로컬 렌더·접근성 점검을 작성한다. 시안의 예시 숫자는 운영 성과가 아니다.
3. 감독자: 계약과 실패 회귀 검사 → 최소 SQL 수집/집계 → 로컬 SQL/권한/중복/기간/코호트 검사. 기존 마이그레이션을 수정하지 않고 새 파일만 추가한다.
4. 확인된 계약으로 실제 클라이언트 입구와 관리자 화면을 연결하고 예외·중복·계정 전환·미수집 상태를 검증한다. 같은 파일은 한 담당자만 편집한다.
5. 전체 검사와 실제 렌더 → 배포 전 미커밋/누락 감사 → 변경 소스만 커밋. 서버 적용은 검증된 변경만 안전한 dry-run/백업/저장 정의 대조 후 한다. 공개 호스팅·앱 빌드·태그·심사 제출이나 새 정기 작업은 실행하지 않는다.

## 실행 명령과 검증

- `npm test` (Node 실행 가능한 scripts/*.test.mjs)
- `npm run typecheck`
- `npm run lint`
- 기존 PostgreSQL17 Docker의 `supabase test db supabase/tests/admin_performance.test.sql --local` 또는 psql 단일 트랜잭션 rollback 점검. 현재 로컬 스키마 차이는 필요한 실제 정의만 테스트 트랜잭션에 제공한다.
- `npm run export:web`와 `npm run check:public-web`, `npm run check:merchant-web`
- `GLING_LOCAL_ADMIN=1 npx expo export --platform web --output-dir .admin-dist` (기존 로컬 관리자만; 공개하지 않음)
- 실제 기존 UI 또는 로컬 headless 렌더에서 390/1440폭·탭/필터·빈 상태·오류·미수집·0·관측 중·수신/클릭 구분을 확인한다. 새/변경된 컨트롤에는 useInteractionFeedback().play(...)을 연결한다.

## 경계

원자료는 실제 기록에서만 집계하고 안전·권한·동의·탈퇴 삭제·원래 예약을 보존한다. 의존성·유료 서비스·worker 상주·중복 예약/제출·실제 회원 테스트 푸시·관리자 역할 임의 부여·인증 우회를 하지 않는다. 신규 정상 수집과 과거 미수집, 설정/로컬 검증/운영 적용/사용자 앱 도달을 별도로 보고한다. 이미지 생성은 해당 없음.

# 관리자 목록 가독성·다중 필터 개선

사용자 요청: Mobbin MCP 사례를 참고해 Gling 관리자 표를 더 조밀하고 읽기 쉽게 만들고 검색 페이지에 다중 필터를 추가한다. 기존 Gling 색상과 로컬 전용 관리자를 유지한다.

## 조사와 적용 기준

2026-09-21 Mobbin MCP에서 실제 화면을 확인했다.
- [Linear](https://mobbin.com/screens/ed670cda-0527-4716-a1a6-0159f12c4f42): 짧은 행, 일관된 정보 위치, 필요한 조건만 필터 메뉴에 노출.
- [Docusign](https://mobbin.com/screens/b5c686e8-3354-42f7-a8f6-7cd067f9561f): 이름·추가일·상태 열 구분, 검색과 복수 조건, 초기화.
- [Sprig](https://mobbin.com/screens/170bfb16-d635-40e7-a931-78d473d9e82c): 사용자 목록의 열 정렬과 별도 조건 영역.

현행 게시글 화면을 캡처해 확인: 도시 칩이 넓은 공간을 차지하고 제목·작성자·긴 ID·도시·시간이 한 줄에 혼재한다. 사용자 목록 코드는 이름·생년월일·ID를 여러 줄로 쌓고, 넓이가 1000px 미만이면 다시 세로로 쌓는다. 전체 ID와 생년월일은 기존 회원 상세로 옮겨 접근성을 유지한다. 운영 원자료가 포함된 캡처는 Git 밖 `~/Library/Application Support/gling/operations/admin-design-2026-09-21/`에 보관한다.

## 구현 범위와 수용 조건

- 사용자: 약 56px의 2줄 표, 열 제목, 상태·계정 배지, 가입/최근 로그인일, 회원 이름을 통한 기존 상세. 좁은 화면에서는 표 영역만 가로 스크롤.
- 사용자 필터: 계정 유형·도시·상태·로그인 방식 복수 선택, 최근 가입 기간, 서버 정렬, 검색·초기화. 같은 필터 안에서는 OR, 서로 다른 필터끼리는 AND. 전체 DB에서 필터링한 후 50명 페이지와 총수를 계산.
- 게시글·대화·AI 안전·감시어·오류·신고: 공통 검색/다중 선택/초기화, 짧은 요약 행과 펼친 전문. 현재 불러온 데이터가 조회 범위임을 표시하고 더 보기를 유지.
- 원본 증거·관리자 권한·감사 로그·조치 확인은 유지한다. 필터로 신고 선택이 바뀌면 이전 신고의 처리 메모가 따라가지 않게 한다.
- 브라우저 기본 체크박스·select·button·details를 사용한다. 키보드 조작, 포커스 링, 44px 조작 영역, 표의 열 제목을 유지한다. 새 의존성 없음.

## 후속 개선 후보

게시글·대화·신고 등은 현재 불러온 페이지를 검색하므로 다음 우선순위는 이 목록들의 서버 전체 검색이다. 저장한 필터 뷰는 반복 사용 패턴을 확인한 뒤 추가한다. 이번 작업에는 일괄 정지/삭제·개인정보 CSV 내보내기를 추가하지 않는다.

## 실제 검증 결과 (2026-09-21)

- Node 관련 테스트 14개, SQL 권한·복합 조건·총수·페이지·정렬·입력 검증 테스트 30개 통과. TypeScript, 수정 파일 ESLint, Expo 관리자 export, diff 공백 검사 통과.
- 0077 사용자 다중 필터 RPC를 운영 DB에 적용했다. 최종 관리자 export를 로컬 관리자 제공 디렉터리에 반영했다.
- Orca 실제 화면: 사용자 행 56px, 게시글 46px, 신고 64px. 사용자 계정 유형+도시 복합 필터, 초기화, 100명까지 더 보기와 ID 중복 없음 확인.
- 390px 화면에서 문서 너비 390px 유지, 사용자 표만 가로 스크롤. 데스크톱 필터 메뉴는 한 개씩 열리고 감시어 필터가 목록 컨테이너에 잘리지 않음을 확인.
- 신고에 미저장 메모를 작성한 뒤 대상 필터로 신고가 바뀌면 메모가 비워짐을 확인. 관리 조치는 실행하지 않았다.
- 사용자 전체 DB 검색과 다른 목록의 불러온 범위 검색을 구별해 표시한다. AI 안전·대화·오류의 모든 데이터 상태를 브라우저에서 개별 검증하지는 않았으며 관련 조건 로직은 위 테스트로 검증했다.

## 신고 일괄 처리 후속 요청

미처리 신고 개별/보이는 전체 선택, 공통 메모(1,000자), 기각·경고·정지·콘텐츠 숨김을 추가했다. 실행 전 건수·동작·메모 확인, 처리 중 중복 실행 차단, 필터 변경 시 선택 해제, 사용자 신고 혼합 시 콘텐츠 숨김 비활성화를 적용했다. 기존 moderate_report RPC를 신고별 순차 호출하므로 권한·행 잠금·감사 기록을 유지한다. 성공/실패 건수와 실패 ID를 구분하고 성공 건을 재선택하지 않는다. 동일 회원의 복수 신고는 신고별 알림이 발생함을 표시한다.

타입 검사·ESLint·관리자 export, 일괄 처리 부분 실패/중복 ID 테스트와 신고 필터 테스트 통과. Orca에서 전체 8건 중 미처리 7건 선택, 혼합 대상 숨김 비활성, 7건 확인창의 취소, 필터 변경 시 0건 선택을 확인했다. 실제 운영 신고에는 조치를 실행하지 않았다.

## 접속 위치 표시 확인

현재 수집 경로는 인증 세션 IP와 동의 기반 기기 위치이며 IP를 도시/국가로 변환한 저장값은 없다. 사용자 목록 최근 로그인 셀에 이미 RPC가 반환하는 세션 IP를 추가하고 도시 열을 선호 도시로 명확히 했다. 좌표·정확도·측정 시각은 기존 회원 상세의 위치·접속 카드에서 제공한다. 외부 IP 위치 조회나 새 수집은 추가하지 않았다. 타입·ESLint·export와 관련 Node 테스트 10개 통과.

# 게시글·자동 홍보 사진 수 (2026-10-08)

최신 앱 수량 지시(2026-10-11): 글링 전체 카테고리 작성·수정·업체 초안·MCP·서버는 최대20장/21장 거부로 변경한다. 아래2026-10-08의10장 앱 한도는 이 지시로 대체한다. Instagram·네이버 카페의 별도 수량과 일정은 유지한다. [새 검증/배포 명세](post-photo20-2026-10-11.md).

사용자 요청: Instagram 소개 앞 사진·정보 카드 5~9장 + 마지막 고정 글링 소개 1장 = 전체 6~10장. 기존 표지·사진·일정/방문 정보·소개 순서와 디자인을 재사용한다. 원본 사진은 4~8장이며 일정/방문 정보 카드가 소개 직전에 붙는다. 소개 문구·브랜드는 행사/장소에 따라 바꾸지 않는다. 사진이 부족하면 중복 크롭으로 채우지 않고 기존 최소 구성/사용권 기준을 지킨다.

글링 앱 작성·수정·업체 초안과 서버 RPC/테이블 모두 최대 10장, 11장은 업로드 전 또는 서버에서 거부한다. 원본·썸네일 순서와 실패 정리, RLS·안전 검증을 보존한다. Expo 57 / 기존 Python 렌더러 / PostgreSQL을 사용하며 새 의존성은 없다.

실행 순서: 수량 경계 테스트 → 공통 상한/안전한 추가 migration → 동적 렌더/고정 소개 → 기존 제작·검수 automation prompt 갱신 및 native 재조회. 기존 job ID·계정·workspace·일정·기한·hold·게시/예약 영수증을 보존한다. 실제 공개 게시/유료 호출/기존 예약 교체는 이번 수량 변경에 포함하지 않는다.

검증: Node 기존 업로드/수정/업체 테스트, 렌더러 6/중간/10장 및 잘못된 수량·고정 소개 테스트, SQL 10장 허용·11장 차단 및 RLS/업체 검증, 전체 npm test·TypeScript, 기존 GUI coordination check, native prompt/schedule readback. 앱스토어 바이너리 업데이트는 별도 배포 단계다.

최종 검증: 앱 Node 441개 중 440개 통과·기존 1개 skip, TypeScript·변경 공용 파일 ESLint 통과. 렌더러 3개 검사에서 6~10장·고유 사진 순서·고정 소개 및 실제 1080×810 10장 내보내기를 확인했다. 1080×1920 10장과 33초/990프레임의 별도 YouTube/TikTok 원본 테스트도 완료했다(실제 Instagram 음악/내레이션 완성본이 아님). 운영 DB 0134를 적용하고 10장 일반/중고 글·수정·업체 사진, 11장·다른 작성자·중복 차단 및 권한 보존을 rollback 검사했다. 네이버 카페 외부 게시의 기존 별도 6장 계약은 변경하지 않았다. 원래 자동화 2개를 재사용해 prompt·일정·workspace·소유권 재조회, 새 작업·수동 실행 0개.

# Webshop backend implementation and verification

The additive migration `20261023180000_webshops.sql` implements the seven shared RPCs plus the city descriptor batch `get_city_webshops(p_city_id text)`. It inserts no business, place binding, menu price, quote or order. The existing AAL2 administrator guard and `analytics` access log remain authoritative; configuration and report mutations also retain before/after or report audit metadata. Every new table is private, has RLS enabled, and grants no direct client/service access. Public city lists are bounded to 1,000 descriptors/links in stable order.

The redirect accepts only the inspected Canadian `order.store` / `www.order.store` store-path form. Registry destinations contain no query, credentials, fragment or port. The function adds fixed `utm_source=gling`, `utm_medium=referral`, `utm_campaign=webshop` and business UUID `utm_content`. Request fields are exactly `merchantId,eventId,session,platform,source`; arbitrary/duplicate fields fail closed. HEAD reads the public descriptor and never invokes the click logger. GET calls the service-only, idempotent resolver before responding. Referrer policy preserves the source origin.

Events retain a random correlation session and an internal flag, without user identity, IP, user agent or device fingerprint. A business owner/operator or administrator identifiable on the sheet-view RPC marks the merchant/session internal. Concurrent or earlier anonymous clicks in that session inherit this flag. Unidentified visitors remain external; clicks do not establish an order.

Public visibility reuses `get_merchant_profile`, including consent, current business status and viewer privacy rules. Place keys are unique across businesses, city ID must match the selected business, and links can remain when its webshop is disabled or absent. The administrator supplies an already verified exact branch key; an OSM ID alone cannot establish its physical location. No name-based association or external geocoder is used.

Report periods are half-open `[start,end)` and contain at most 5,000 rows over at most 366 days. Initial currency is CAD. Only explicit report evidence and the allowlisted non-customer order fields are accepted. Evidence rejects controls, email markers and long card-like digit runs; the operator still must exclude personal data from free text and provider IDs. Identical report retry is idempotent, a conflicting report/order retry is rejected, and the same external order in multiple reports contributes once. An explicit empty verified report records measured zero; no report yields null financial fields. Corrections changing an existing order require a separately designed audited correction workflow; conflicting data is never silently overwritten.

Financial totals sum observed report data only. Report availability means at least one verified report overlaps the selected period; it does not certify continuous provider-report coverage. Missing businesses/days retain nulls in their breakdown. Daily buckets use UTC. Cancelled orders contribute no order count or revenue; refunded orders remain known orders and contribute their food subtotal less refunds. Attributed revenue/orders exclude `unattributed`. Commission is estimated only when both basis and scope are explicitly configured, using net food subtotal and rounding the per-business aggregate to integer cents. Delivery, service, tax and tip never enter this basis. No payout/settlement state is created.

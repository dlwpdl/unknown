# 글링 지역 업체 홍보 BM · 시범 운영과 성과 측정

2026-10-07 · 사용자 제안에서 출발한 설계. 업체 참여·지불 의사·성과는 미검증이다. 이번 작업은 로컬 코드 점검과 설계 기록이며, 업체 연락·콘텐츠 등록·분석 연결·결제·자동화를 실행한 기록이 아니다.

2026-10-07 후속 구현: 사용자가 업체 관리·원문 버튼 분석·편집 가능한 보고서·AI API/MCP·관리자 2FA를 요청해 기존 어드민/Supabase에 구현했고 migration0117/0118를 운영 DB에 적용했다. 아래 로컬 점검/제안은 구현 전 기록이며 현재 계약과 배포 범위는 [업체 관리 API·MCP](merchant-admin-api.md)를 따른다. 표시 조회수는 최신 사용자 지시에 따라 **작성 시점 누적, 익명·운영 조정 포함**이라고 표시해 보고서에 포함하며 실제 열람·원문 클릭·주문과 혼동하지 않는다. 아직 실제 업체 동의·등록·게시·영업·결제·수요 효과는 검증하지 않았다.

## 사업 흐름과 판매할 가치

캐스모·헬로밴쿠버 등에서 홍보하는 지역 업체를 찾고, 사장님의 허락을 받은 원고를 글링 해당 도시·게시판에 무료로 소개한다. 업체별 반응 보고서를 제공한 뒤, 필요한 업체에 2주 또는 월 단위 유료 운영을 제안한다. 기존 커뮤니티 이용을 중단할 필요는 없다.

글링은 최신 지역 콘텐츠를 확보하고, 업체는 추가 홍보 경로와 확인 가능한 반응을 얻는다. 업체의 반복 등록 수고, 성과를 모르는 문제, 채용·메뉴·주문 정보 관리가 실제 구매 이유인지는 사장님께 확인한다. 콘텐츠 확보와 유료 고객 확보는 별개의 성과다.

유료 상품은 허락받은 글 등록·수정, 기간별 성과 보고, 결과에 따른 다음 홍보 개선이다. 제공 작업·게시 수·기간·CAD 요금·세금·종료 조건을 구체적으로 제안한다. 상단 고정·추가 노출·주문·채용 성과는 구현·검증·계약 전 약속하지 않는다. 채용은 필요 기간의 캠페인, 반복 주문 업장은 월 운영을 시험할 수 있지만 가격·지불 의사는 아직 미확정이다.

기존 무료 글·모임·대화 이용을 유지한다. 업체 운영 패키지는 이전 게시글 홍보의 구매 노출량 방식과 별도이며, 이 설계로 그 요금·기능을 변경하지 않는다. 기존 무료 소개를 사후 결제로 전환하거나 자동 청구하지 않는다.

## 최소 시범 운영 제안

밴쿠버 한 도시, 카페·음식점 등 한 업종의 5곳, 실제 글 공개 후 14일 무료 운영을 권한다. 이는 제안이며 확정 일정이 아니다. 주문·방문부터 배우고 채용은 별도 목적·보고서로 확장한다. 기존 지인·업체 소개가 있다면 먼저 활용한다.

1. 업체의 현재 목적과 기존 홍보 방법을 확인한다. 이미 글링에 등록된 업체·글이면 재사용한다.
2. 대상 원고·사진·연락 경로·무료 기간·이후 선택형 유료 제안을 설명하고 허락을 기록한다.
3. 업체→캠페인→게시글 연결과 운영자/테스트 제외를 준비한다. 실제 업체 수신 경로로 안내한다.
4. 정상 앱 등록 후 도시·본문·사진·버튼·링크를 재조회한다. 공개 시각부터 무료 기간을 계산한다.
5. 변경·마감 정보를 반영하고, 7일 중간 점검·14일 보고에 실제 반응과 수집 공백을 기록한다.
6. 사장님이 받은 문의의 유효성·주문·방문·지원 여부를 확인한다. 구체적인 유료 조건을 제안하고 실제 수락·결제·갱신을 따로 기록한다.

무료 참여 수, 보고서 열람, 유료 운영 의향, 실제 결제, 재계약은 다른 단계다. 반응이 없거나 측정이 불완전하면 그대로 보고한다. 등록·수정·보고·지원에 쓴 시간도 기록해 남는 돈을 판단한다. 소수 업체의 가치와 실제 결제 반응을 확인한 뒤 확대한다.

## 허락과 최신 정보 유지

접근을 제한한 운영 원장에 업체·담당자, 원문 URL, 허용 원고/사진 또는 향후 글의 범위, 글링 게시·수정 범위, 도시·게시판, 무료 기간, 연락/주문 경로, 변경·철회 방법, 동의 시각과 근거를 남긴다. 한 글의 허락을 모든 미래 글의 허락으로 확대하지 않는다.

업체가 직접 제공하거나 권한을 확인한 원고·사진을 우선 사용한다. 경쟁 커뮤니티의 자체 제작물·다른 회원 사진을 업체 허락만으로 복사하지 않고 출처 사이트의 접근·재사용 조건도 확인한다. 업체명과 허락받은 소개라는 사실을 밝히고, 유료 소재에는 해당 광고·제휴 표시를 적용한다.

원문·마지막 확인 시각·마감일을 연결하고 기존 글을 수정한다. 같은 홍보를 반복 복제해 피드를 채우지 않는다. 채용 종료·주문 중단·동의 철회는 게시 상태와 버튼에 반영한다. 기존 listing은 14일 만료 구조이므로 월 운영에 단순 자동 연장을 약속하지 않는다.

업체 글은 글링 앱 관련 게시판에서 운영한다. 현재 문화·행사 중심 Instagram/Reels와 개인 Threads에 구인구직·일반 업체 홍보를 자동 편입하지 않는다.

## 무엇을 측정할지

업체 ID→캠페인 ID→게시글 ID→행동 기록→보고서로 연결한다. 캠페인에 목적, 실제 공개/종료 시각, 도시 시간대, 콘텐츠 버전과 동의 근거를 연결한다. 채용과 주문을 같은 전환으로 섞지 않는다.

| 이벤트 | 발생 조건 | 보고서 이름 |
|---|---|---|
| `merchant_post_opened` | 실제 글 상세가 표시될 때. 목록 로딩·백그라운드 요청 제외 | 상세 열람 |
| `merchant_cta_clicked` | 해당 업체의 연락·지도·주문·지원 버튼을 직접 누를 때. 종류별 구분 | 연락/지도/주문/지원 버튼 클릭 |
| `merchant_inquiry_started` | 업체와 연결된 앱 내 대화의 최초 메시지가 서버에 저장될 때. 대화창 열기만으로 집계하지 않음 | 앱 내 문의 시작 — 해당 연결 구현 시 |
| `merchant_conversion_confirmed` | 검증된 완료 응답 또는 사장님 확인 결과가 있을 때 | 확인된 주문/예약/지원 — 근거별 구분 |

최소 컨텍스트는 `event_id`, `merchant_id`, `campaign_id`, `post_id`, 고정된 `action_type`, `platform`, 서버 수신 시각이다. 내부 로그인 계정/메모리 세션 구분은 기존 권한·보관 정책을 유지하며 업체에 노출하지 않는다. 검색어·메시지·이력서·개인 연락처·토큰 포함 전체 URL을 분석 이벤트에 넣지 않는다.

서버가 게시글과 활성 캠페인 연결·허용 행동을 검증한다. 기존 관리자 권한/감사, 요청 상한, 중복 전송 방지, 삭제/보관 정책을 적용한다. 현재 일반 행동 분석은 필드를 엄격하게 제한하므로 임의 ID를 버튼 이름에 끼워 넣지 않는다. 구현 전 기존 RPC 계약을 읽고 최소 컨텍스트를 명시적으로 설계한다.

로그인 회원은 기간 내 계정별 중복을 제거하고, 익명 방문은 확인 가능한 세션 범위를 따로 보여준다. 로그인 인원과 익명 세션을 합쳐 고유 인원이라고 쓰지 않고, 서로 다른 기기·익명→로그인을 임의로 한 사람으로 합치지 않는다. 재전송 중복을 제거하되 실제 반복 클릭은 총 클릭과 중복 제거 수로 구분한다. 운영자·작성자·관리자·seed·심사/테스트 계정, 내부 QA와 알려진 자동 요청을 성과에서 제외한다.

첫 수집 시각·지원 앱 버전·플랫폼별 수집 범위·전송 오류를 보고한다. 옛 표시 조회수에서 새 캠페인 성과를 역산하지 않는다. 수집되지 않은 항목은 `미측정`, 확인되지 않은 결과는 `미확인`, 실제 측정 값이 0일 때만 `0`이다.

버튼 클릭 ≠ 외부 페이지 로드 ≠ 문의/주문/지원 완료다. 전화는 발신창, 지도는 지도, 주문·지원은 외부 이동 시도까지다. 외부 완료는 연동·캠페인 코드/쿠폰·업체 집계 확인이 필요하다. 업체 자체 보고와 시스템 확인 결과를 분리하고, 출처를 모르는 기존 단골 주문을 글링 성과로 배분하지 않는다. 캠페인 코드 사용도 인과적인 매출 증가를 증명하지는 않는다.

피드 노출은 실제 카드 노출 기준을 구현하기 전까지 보고하지 않는다. 열람→버튼 클릭 비율도 동일 기간·모집단·게시글 연결이 확인될 때만 계산한다. 전체 클릭 수를 로그인 회원 열람 수로 나누지 않는다.

## 도구 선택과 다음 구현

추천은 기존 Supabase 분석·관리자 보고에 업체/캠페인 연결과 최소 행동 기록을 확장하는 것이다. 초기 5곳은 작은 비공개 운영 원장으로 관리할 수 있다. 자동 영업, 업체 대시보드, 신규 서버·데몬·유료 분석 서비스를 먼저 만들지 않는다.

GA4는 웹·앱 전체 유입 분석을 함께 볼 때 추가 후보로 남긴다. 웹 태그 하나로 iOS/Android까지 측정한다고 표현하지 않는다. Google은 앱 수집에 Google Analytics for Firebase SDK를 안내하며, 웹 향상된 측정의 외부 클릭은 외부 구매 완료를 뜻하지 않는다. GA4를 넣어도 업체·게시글·행동·완료 연결은 직접 설계해야 한다.

1. 기존 글/권한 기반에 업체·캠페인·게시글 연결과 실제 연락 경로를 최소 확장한다. 별도 주문 시스템을 먼저 만들지 않는다.
2. 상세 열람·CTA 기록과 관리자 업체별 집계를 구현한다. 중복·내부 계정 제외·기간·익명/로그인·권한·오류를 확인하고 실제 앱/웹 행동과 저장 기록을 대조한다.
3. 보고서는 기존 `marketing/templates/social-performance.html`의 현재 글링 브랜드·출력을 활용하되 아래 고객용 항목으로 줄인다. 관리자 원자료를 업체에 전달하지 않는다.
4. 실제 14일 운영 결과·업체 확인·운영 시간으로 요금과 제공 범위를 조정한다. 실제 결제·갱신을 검증한다.
5. 반복 업무가 확인된 뒤 자동화한다. 생성·수정 전 기존 작업·일정·계정·실행·미완료 제출을 점검하고 `automation-coordination.md`의 공용 GUI 큐·원래 기한을 재사용한다. 네이티브 저장 설정과 실제 실행·등록·성과는 따로 검증한다.

## 허락 요청 초안 — 미발송

안녕하세요, 캐나다 한인 모임·커뮤니티 앱 글링을 운영하고 있습니다. 올려주신 [업체명/원고 주제] 글을 보고 연락드렸어요.

괜찮으시면 이 글을 글링 [도시/게시판]에도 2주 동안 무료로 소개해드리고 싶습니다. 허락해주신 내용과 사진만 사용하고, 사장님이 원하시는 연락/주문 경로로 안내할게요. 사용 가능한 원고와 사진을 직접 보내주셔도 좋습니다.

기간이 끝나면 실제 측정한 글 열람과 연락·주문 버튼 클릭 등을 정리해드리겠습니다. 확인되지 않은 클릭을 주문 건수로 말씀드리지는 않습니다. 이후 계속 맡기고 싶으실 때만 유료 운영 조건을 안내드리며 자동 결제는 없습니다. 내용 수정이나 게시 중단도 요청하실 수 있어요.

이 글과 사진을 해당 범위로 소개해드려도 괜찮을까요?

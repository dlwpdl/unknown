## 비즈니스 카테고리 예외 · 사용자 승인 2026-10-23

글링은 게시판이 중심이다. 비즈니스 카테고리의 기본은 ‘새 소식’ 게시글이며, ‘비즈니스 찾기’를 명시적으로 눌렀을 때 별도 안내 목록으로 들어간다. 안내형을 기본 화면으로 올리지 않는다. 사용자는 카테고리마다 탐색 목적에 맞는 별도 배치·카드 크기를 허용했다. 이 범위에서는 공통 PostCard 대신 작은 고정 썸네일과 제목의 BusinessNewsCard를 사용하며, 다른 카테고리와 상세의 기존 카드를 유지한다.

안내 목록은 게시글 페이지를 중복 제거해 만들지 않고 공개 프로필의 가시성 규칙으로 비즈니스별 한 번씩 조회한다. 행은 기존 비즈니스 프로필로 연결하고, 등록 웹샵은 그 프로필의 기존 안내·비교·주문 연결을 쓴다. 버튼·타이포·선택/눌림·소리/햅틱·접근성은 공통 계약을 재사용한다. 시안과 소스 렌더는 `unknown/output/reviews/gling-business-category-concepts-20261023/implementation/`이며, 네이티브 설치·서버 적용·스토어 공개와 구분한다.

기준: 2026-10-19 사용자가 승인한 ‘기존 카드 구성 + 컨트롤 다듬기’ 시안. `/awwwards`의 구성·타이포·상태 완성도 기준을 글링 네이티브 앱에 적용한다. 현재 카드 배치·자료·개인정보·권한·내비게이션을 유지한다. 화면마다 새 스타일을 만들지 않고, 같은 역할에 같은 규칙을 쓴다.

## 선택·눌림·사용 불가 상태

`controlPresentation(theme, state)`가 색과 눌림 표현의 기준이다.

| 상태 | 배경·글자·동작 |
| --- | --- |
| primary | `accent` / `accentInk` |
| secondary 기본 | `card` / `text`, `line` 테두리 |
| secondary 선택 | primary와 같은 배경·글자, selected 접근성 상태도 함께 지정 |
| ghost 기본·선택 | 기본은 투명·text, 선택은 `backgroundSelected`·accent |
| 눌림 | `controlPresentation`은 색만 맡고, 크기 반응은 `FlatPressable`이 맡는다. 네이티브에서 90ms 안에 눈에 보이게 작아지고(`pressedScale`, 너비와 상관없이 약 12pt, 작은 컨트롤 최소 0.94) 놓으면 `ControlMotion.releaseSpring`으로 살짝 튕기며 돌아온다. 사용자 승인 2026-10-31, 2026-11-02 "요새는 무조건 있어야함". 행 전체처럼 부모를 채우는 컨트롤과 disabled·누를 수 없는 요소는 줄이지 않는다. 입체 깊이(그림자·두꺼운 아래 테두리)만 쓰지 않는다 |
| 입체 예외 | 지도 분류 칩의 3D 그림(`assets/images/map-categories`, 사장님 2026-11-04 ⑪)은 그림 안에 든 광택·그림자를 그대로 쓰고, 지도 위에서 읽히도록 그림 가장자리에 옅은 테두리(라이트 흰색·다크 짙은 색)를 둔다. 버튼·칩 바탕을 그림자로 띄우는 것은 계속 쓰지 않는다 |
| 감소된 모션 | 크기 반응을 끄고 opacity0.82만 쓴다. 시트·펼침의 이동은 짧은 페이드로 바꾼다 |
| disabled·busy | opacity0.45, 눌림 효과와 재실행 금지. 접근성 상태·disabled도 실제 컴포넌트에 전달 |
| 키보드 초점 | 숨기지 않는다. 네이티브 초점은 플랫폼 표현 유지, 웹은 테마 accent로 명확한 외곽선 제공 |
| 오류·위험 | 선택 상태로 표현하지 않는다. 기존 오류/위험 의미와 확인 절차 유지 |
| 곧 닫음 | `orange` 글자. 영업시간 줄(`PlaceHours`)에서 1시간 안에 닫을 때만 쓰고 닫는 시각을 같이 적는다. 오류·위험(danger)과 섞지 않는다(사장님 2026-11-05 P6) |

색만으로 상태를 구분하지 않는다. selected·disabled·busy·expanded 같은 접근성 상태와 필요한 체크 표시/설명을 함께 둔다. 저장 중에는 선택 상태를 잃거나 다른 계정의 결과를 붙이지 않는다. 디자인 변경으로 데이터 흐름을 바꾸지 않는다.


## 움직임은 필수 (owner 2026-11-02)

사용자 원문: "앱이 너무 밋밋해져서 보기싫어", "움직임이나 효과 넣지않기는 언제했는지 모르겠는데? 요새는 무조건 있어야함". 2026-10-19에 넣었던 '공통 컨트롤에 모션을 추가하지 않는다' 규칙은 폐기한다. 새 화면·컨트롤은 누름(작아졌다 돌아옴), 열림·닫힘(들어온 길로 나감), 목록·내용 등장(짧은 페이드·올라옴), 전환 중 로딩(가운데 `GlingLoader`)을 반드시 갖춘다. 동작 줄이기에서만 이동을 페이드로 바꾼다.

이 기준은 탭 첫 화면만이 아니라 상세 화면과 그 안에서 열리는 시트·메뉴·모달·하위 화면·확인창까지 전부 적용한다(owner 2026-11-03 "전체적으로 상세화면까지 네스티드된 곳 딥하게 다 봐야함"). 점검할 때는 그 영역에서 열 수 있는 화면 목록부터 만들고 하나씩 확인한다.

| `RaisedActionButton`의 `tone="secondary"` | 같은 화면의 보조 행동 |
| `StateCard`의 `layout="start"` | 할 일 화면 맨 위의 현재 상태. 왼쪽 정렬이고 `mark`(느낌표·빼기·체크)와 아래 내용(단계 표시 등)을 받는다. 화면 전체가 비었거나 오류일 때는 기본 가운데 정렬을 쓴다 |

호스트 화면에서 호스트 관리는 상태·할 일 하나·관리 다섯 줄의 순서를 유지하고, 맨 아래 큰 버튼은 그때 가장 급한 일 하나만 맡는다.

## 아이콘

`IconSize.toolbar=21`, `inline=16`, `chevron=14`, `avatar=28`을 사용한다. 보이는 아이콘 크기와44px 터치 영역은 별개다. 같은 행동에는 같은 SF Symbol/Material 의미를 쓴다. 아이콘 전용 버튼에는 읽을 수 있는 접근성 이름을 지정한다. 글자 크기를 키웠을 때 아이콘이 텍스트를 밀거나 덮지 않게 확인한다.

화면 제목, 메뉴·카테고리, 본문, 설명을 내용의 역할로 고른다. 화면 이름마다 다른 글자 크기를 만들지 않는다. 메뉴와 카테고리의 기본은 label이며 작은 설명은 supporting이다. micro는 보조 표식에만 사용하고 주요 메뉴 이름에는 쓰지 않는다. 한국어·영어 모두 글자 확대를 허용한다. 고정 높이로 여러 줄 텍스트를 자르지 않는다. 긴 도시 이름은 버튼의 접근성 이름을 온전히 유지하고, 헤더는 좁은 화면/큰 글자에서 줄바꿈한다. 기존 ThemedText의 small/smallBold/default는 호환을 유지하며 각각 supporting/label/body 역할이다.

## 간격과 정렬

기존 `Spacing`의4·8·16·24·32px를 사용한다. 아이콘과 짧은 라벨은4–8px, 관련 컨트롤은8px, 화면 좌우는16–24px, 섹션 사이는24–32px를 기본으로 삼는다. 같은 화면의 고정 헤더와 목록 시작선을 맞춘다. 카테고리는 한 줄에서 스크롤하고 상세 필터는 시트에 둔다. 메뉴 열기/닫기에서 카드나 목록을 다른 구조로 재배치하지 않는다.

홈의 작은 줄(가볼 곳·행사)은 `MiniCard`의 사진 높이·모서리를 함께 쓴다. 이름은 label, 날짜·장소·가격 같은 보조 줄은 caption이다. 행사는 고정 너비로 가로로 넘기고 다음 카드가 조금 보이게 하며, 가볼 곳은 세 칸으로 나눈다. 정보가 없는 줄(가격 등)은 '정보 없음'을 쓰지 않고 줄째 뺀다.

CityPicker는 도시를 섹션마다 테두리 없는 연속 목록으로 묶고, 첫 행과 마지막 행에 기존 field 반경을 쓴다. 섹션 이름·도시 이름·위치 안내는 `Spacing.three` 안쪽 시작선을 맞춘다. 국가 그룹에는 field 반경, 각 선택에는 action 반경을 적용해 캡슐이 원형으로 눌리지 않게 한다. 기본 글자 크기에서는 국가를 같은 너비로 나누고, 큰 글자에서는 현재 국가의 내용 너비를 유지하며 준비 중인 국가를 줄바꿈한다. 라벨을 줄이거나 자르지 않는다. GPS는 ghost 보조 행동으로 표현하고 선택한 도시는 체크와 선택 배경으로 구분한다.

## 반응·소리·햅틱

기존 `useInteractionFeedback().play(kind)`만 사용한다. 선택·탭·일반 도구는 selection, 주요 행동은 기존 reaction, 오류는 warning, 실제 저장/게시 성공은 기존 success/전용 완료 피드백을 유지한다.

해낸 순간의 그림(사장님 2026-11-08 "컨펌 답 (3D 축하): 추천대로 28곳", 점검표 `unknown/output/reviews/celebration-3d-2026-11-08/`): 드문 처음(모임 열기·첫 글·인증 레벨·멤버십 첫 구매·첫 모임 다녀옴·초대 연결)만 전면 3D 축하(어두운 화면, 클레이 그림이 튀고 클레이 색종이, 로고는 밝은 글자판 `gling-3d-wordmark-dark`)를 쓰고, 그 밖의 성공(success·meetup·meetupRequested)은 작은 클레이 링(3D 배지 + 색종이 다섯 개, 약 0.65초)이다. 저장 풀기·팔로우 끊기처럼 되돌리는 일과 지도 내 위치 찾기에는 success를 쓰지 않는다. 2D 디자인·웹은 같은 자리에 평면 그림을 쓰고, 동작 줄이기는 움직이지 않는 그림으로 보여 준다. 새 전면 축하는 `interaction-feedback.tsx`의 `CELEBRATIONS` 표에 한 줄로 더하고, 정말 드문 순간에만 쓴다. 동일 동작의 중복 피드백을 추가하지 않는다. 스위치·칩 같은 작은 조작은 selection만 쓰고, 실제 저장이 끝난 큰 행동만 success를 쓴다. 컴포넌트와 호출자 중 누가 play를 담당하는지 기존 계약을 확인한다. 소리·햅틱 사용자 설정과 reduced motion을 존중한다. 새 오디오 엔진·저장 키·전역 애니메이션을 만들지 않는다.

## 새 기능을 만들 때

1. 기존 컴포넌트와 이 문서에서 같은 역할을 찾는다. 우선 재사용한다.
2. 스타일은 `ControlStyles`, `Typography`, `IconSize`, 기존 `Colors`·`Spacing`에서 가져온다. 새 페이지에서 동일 역할의 숫자/색/눌림 로직을 복사해 만들지 않는다.
3. 새 변형이 꼭 필요하면 공통 토큰/컴포넌트에 추가하고 문서·관련 행동 검사·실제 렌더를 함께 갱신한다. 예외는 이유·범위·적용 조건을 기록한다. 별도 사용자 승인 단계를 만들지 않는다.
4. 기본·선택·눌림·disabled·busy·오류·빈 상태, 다크/라이트,320/390px, 한/영, 큰 글자, 감소된 모션, 키보드 초점을 확인한다. 해당 없는 상태는 구분한다.
5. 신규 컨트롤은 접근성 이름/상태와 기존 피드백을 연결한다. 데이터·권한·계정·안전 경계는 그대로 검증한다.
6. `/awwwards` 관점으로 실제 화면을 본다. 글자 위계·간격·아이콘 무게·버튼 상태가 같은 체계인지 두 차례 이상 렌더로 확인한다. 화려한 효과의 개수나 자체 점수는 품질 증거가 아니다.

## 네이티브 경계

NativeTabs의 라벨·선택색·배경·배지를 기존 Expo57 API로 다듬는다. 탭 라벨 크기는 플랫폼 기본값을 사용하며 micro 크기로 덮어쓰지 않는다. iOS 시스템 유리·플랫폼별 탭 규격은 HTML처럼 임의의 픽셀 배치로 재작성하지 않는다. HTML/RNW 시안 검수와 실제 기기·시뮬레이터 검수를 구분한다. 기존 단독 설치 담당과 배포·구버전 제공 정책을 유지한다.

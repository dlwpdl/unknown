# Retained chat evidence

The original worker concatenated every earlier message body and sent only its first 12,000 UTF-16 characters. A late dangerous version could therefore remain in storage without reaching the classifier. The existing queue now keeps private progress: each claim reviews one entire retained body or one bounded current-context segment. History progress survives new edits. Context is filtered again before every delayed segment. The queue remains pending until all versions and segments finish, preserves the highest detected risk across successes, failures and later edits, and raises high-risk alerts immediately. A separate risk signal timestamp advances only when an accepted segment finds high or critical risk. The investigation dashboard uses that timestamp, so a new critical finding reopens a cleared high-risk case while benign progress and final completion leave it closed. Successful progress resets the failure counter; a five-minute abandoned lease can resume in the same scheduled worker. A stale claim cannot advance or fail a newer claim.

The existing provider, model, privacy setting, schedule and per-run claim limit remain in use. Oversized input is rejected before a provider request instead of silently losing its tail. The production v18 trust-review routes and consent-aware conversation context remain available. Completion and failure-recording RPC errors are isolated to their queue item; later claimed posts still run.

Deleted image paths stay in private history. The retained-image Storage policy requires the existing live AAL2 admin boundary and records the message and sender through `log_admin_access`. A participant cannot use another sender's deleted attachment; AAL1 and expired admin sessions are denied. Uploader DELETE is restricted to unbound uploads. A private guard sees hidden messages and retained history, and shares the existing attachment-send lock so failed uploads can be cleaned up without removing sent evidence. Other buckets and service-owned legal cleanup keep their existing permissions. The existing admin investigation RPCs, direct history restrictions and append-only review records are preserved.

Validation: the actual worker/analyze code passed three offline VM regressions with zero network calls, including a failed message completion and failed error RPC followed by a successfully processed post. The full Node suite passed 771 cases with one existing skip; TypeScript and lint passed. Approved bubble UI files remain byte-identical.

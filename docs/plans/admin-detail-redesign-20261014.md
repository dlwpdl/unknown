# 관리자 상세 화면 정보 정리

사용자가 모임 상세의 과도한 정보를 지적하며 관리자 메뉴와 상세를 직접 열어보고 함께 리디자인하도록 요청했다. 기존 밝은 관리자 테마와 데이터·권한 계약을 유지하고, 내용을 읽는 화면에서 필요한 정보가 먼저 보이도록 정리한다.

## 기준

- 기본 화면은 대상 이름, 현재 상태, 핵심 내용과 해당 작업에 필요한 정보에 집중한다.
- 일반적인 참여 조건, 등록 시각, 식별자, 경로, 설정과 설명은 이름이 분명한 펼침 안에 둔다. 제한·위험 신호·읽기 실패와 수집 여부는 숨기지 않는다.
- 펼침을 닫거나 기존 탭을 바꿔도 편집 중인 값과 검토 메모를 보존한다. 권한·감사·모니터링·파괴적 조치의 확인 절차는 유지한다.
- 기존 컨트롤과 피드백을 재사용하고, 좁은 화면·키보드·44px 조작 영역을 확인한다. 새 서비스, 의존성, 정기 작업은 추가하지 않는다.

Design·Apple Design·Frontend Design을 적용했다. Mobbin의 [Meetup](https://mobbin.com/screens/a4f05e86-ab7f-4461-b266-c5ae6d61b336)에서 제목·주최자·일정과 부가 동작의 분리를, [Calendly](https://mobbin.com/screens/2cb90a92-7689-4166-92ff-86607ae0a3ca)에서 접힌 설정 구성을 실제 이미지로 확인했다. 별도 HTML 시안은 예시 데이터이며 390/1440px 렌더와 동작을 검수하고 기존 글링 프로젝트의 Orca Browser에서 열었다.

## 적용 범위

모임 상세는 소개·주최자·인원과 실제 제한을 먼저 보여준다. 긴 소개는 원문을 보존하면서 펼칠 수 있고, 일반 조건·신청 질문·등록 시각·ID는 추가 정보에 둔다. 대화방이 하나이면 중간 목록을 거치지 않고 해당 모임의 메시지를 읽는다. 여러 방과 없는 방도 별도로 처리한다.

회원 상세는 계정 관리와 활동을 분리하고 중복된 활동 선택을 하나로 모은다. 게시글은 본문부터 읽고 수치·노출 설정을 펼친다. 벤더의 연결 글은 업체 정보 탭에 모으고 계정·소유 설정을 접는다. 전체 성과의 여덟 영역은 요약을 유지하며 펼칠 수 있고, 집계 설명을 별도로 둔다. 신고와 대화 검토는 현재 근거·메모를 우선하며 추적 식별자·과거 이력은 펼쳐서 확인한다. 좁은 신고 상세의 목록 복귀 오류도 수정한다.

## 직접 확인한 범위

기존 정상 MFA 관리자 세션에서 13개 기본 메뉴와 분석의 7개 탭을 열었다. 모임 정보·신청·대화 목록, 회원 상세, 게시글 본문·편집, 전체 대화의 메시지와 검토 화면, 신고 상세, 벤더 성과·정보도 확인했다. 발송·삭제·권한 변경·AI 연결 발급처럼 운영 상태를 바꾸는 버튼은 실데이터에서 실행하지 않는다. 실제 화면과 예시 렌더 검증은 구분한다.

직접 점검 중 앱 오류 조회가 HTTP405로 실패하는 것을 확인했다. 운영 함수가 `STABLE`인데 접근 감사 로그를 쓰고 있어 PostgREST의 읽기 전용 트랜잭션과 충돌한다. [공식 트랜잭션 계약](https://github.com/PostgREST/postgrest/blob/main/docs/references/transactions.rst)을 확인하고 기존 함수의 volatility만 수정한다. 함수 본문, MFA 검사, 권한과 감사 기록은 보존한다. SQL 회귀는 변경 전 실패하고 변경 후 4개 통과 후 rollback했다.

## 검증과 반영 기록

전체 Node 검사 1,020개 중 1,019개 통과·조건부 1개 skip, 타입·전체 lint·비공개 관리자 export가 통과했다. 세부 담당자의 회귀 검사는 기존 소스에서 실패한 뒤 변경 후 통과했다. 실제 운영 API 복구와 최종 브라우저·배포 영수증은 비공개 operations의 `admin-detail-redesign-20261014/`에, 격리된 예시 화면과 검사 로그는 `.release/`에 보관한다.

390px 실제 export의 캡처에서 신고 상세 위에 뒤쪽 페이지 이동 버튼이 그려지는 문제를 확인했다. 포인터 위치 검사를 추가해 변경 전 실패를 확인하고, 상세가 열린 동안 해당 큐의 쌓임 순서를 올린다. 메모·대상·본문과 목록 복귀 상태는 유지한다. 회원 패널의 캡처는 등장 애니메이션이 끝난 뒤 검수한다.

원본 checkout의 별도 미커밋 자료를 덮어쓰지 않는다. 공개 웹·네이티브 빌드·태그·심사 제출과 기존 자동화 일정·소유권은 이 작업에서 변경하지 않는다.

# 칠링: 개발 명세 초안

상태: 2026-09-17 사용자가 HTML 시안과 실제 앱 구현을 승인했다. iOS 1.0.1 (25)에는 포함하지 않는다. 무료 기본 흐름을 연결하며 운영 배포·새 빌드 업로드는 별도 검증 후 진행한다.

## 확정된 방향

- 앱 이름은 당분간 글링, 하단 탭 이름은 모임으로 유지한다. 내부 선택은 칠링(일회성) / 모임(정기모임)이다. 오늘 탭도 유지한다. 아래 초안의 반짝/우리 모임 명칭은 이 결정으로 대체한다.
- 친구·취미·여행·파티를 중심으로 만남을 제공한다. 데이팅 항목이나 연애 의향 수집을 추가하지 않는다. 사용자 간 자연스러운 관계 발전을 제한한다는 의미는 아니다.
- 일회성 만남과 지속 모임을 목록에서 확실하게 구분한다.
- 무료 사용자도 개최·참여·프로필 작성과 확인·승인·정원 설정·기본 신청 질문·공지·신고·차단을 사용할 수 있다.
- 유료는 추가 운영 기능이다. 행사 개최 자체를 유료 전용으로 만들지 않는다.
- 무료 참여자의 신청이나 승인에 호스트의 유료 기능 비용을 전가하지 않는다.

## 구조 선택

권장: 기존 글링 모임/신청/대화 기능을 확장한다. 현재 `meetups.tsx`는 `FeedScreen meetupsOnly`를 사용하며, `posts.room_preview`, `meetup_requests`, 그룹 `conversations`에 기존 승인·정원·차단·자리 계산이 있다. 기존 RPC를 깨지 않고 새 기능을 추가한다.

대안 1: Luma 외부 연결은 빠르지만 프로필 공유·차단·멤버십·신청 상태가 두 서비스로 갈라진다. 현재 범위에서는 계정/API/결제를 연결하지 않고 운영 경험을 참고한다.

대안 2: 모임 전체를 새 서비스로 재작성하면 기존 채팅·회원·신고와 중복된다. 선택하지 않는다.

## 첫 개발 단위: 무료 기본 흐름

1. 모임 탭에 `칠링 · 일회성` / `모임 · 정기모임` 선택을 제공한다. 카드에도 이름과 일정/주기를 텍스트로 표시한다. 색만으로 구분하지 않는다.
2. 둘러보기는 프로필 없이 가능하다. 새 행사 개최 또는 첫 신청 때 별도 칠링 프로필을 작성한다.
3. 프로필 초안: 기존 닉네임·아바타 재사용, 한 줄 소개, 관심사, 질문형 소개 2개. 추가 사진과 추가 질문은 선택 사항이며 첫 단위에서는 사진 업로드 경로를 새로 만들지 않는다. 실명·직장·소득·연애 의향은 요구하지 않는다.
4. 호스트 프로필은 행사 상세에서 볼 수 있다. 신청자는 제출 직전 호스트에게 공유되는 자기소개와 답변을 미리 확인한다. 신청자 프로필을 전체 회원이나 다른 신청자에게 자동 공개하지 않는다.
5. 반짝은 시작·종료 시각과 시간대, 지역, 정원, 소개, 기본 질문 1개를 받는다. 종료 이후 신규 신청·승인은 서버에서 막는다. 종료는 원본 콘텐츠나 신고 기록 삭제가 아니다.
6. 우리 모임은 소개·활동 지역·활동 주기·정원·기본 질문 1개를 받는다. 무료로 지속 모임을 운영할 수 있다. '매주 토요일'이라는 주기 안내와 유료 자동 반복 일정 생성은 다른 기능이다.
7. 신청 → 호스트 검토 → 승인/거절 → 승인된 회원의 기존 그룹 대화 접근을 재사용한다. 중복 신청, 정원 경쟁, 호스트/신청자 차단, 정지 계정은 서버가 검사한다.
8. 공개 행사 정보에는 대략적인 장소만 포함한다. 상세 집결 정보는 승인된 회원에게만 보이며 목록·알림·공유 링크에 새지 않아야 한다.

기존 모임은 일회성으로 추정하지 않고 지속 모임으로 호환한다. 기존 회원에게 프로필 미작성으로 퇴장이나 대화 접근 차단을 적용하지 않는다. 신규 신청/개최에만 작성 조건을 적용한다.

## 후속 개발 단위: 유료 운영 도구

| 무료 기본 | 유료 확장 |
|---|---|
| 프로필 작성·확인, 행사 개최·참여 | 동시에 모집하는 행사 수 확대 |
| 기본 승인제 | 행사 복제·반복 일정 생성 |
| 정원·기본 질문 1개 | 추가 질문·대기자 관리 |
| 공지·신고·차단 | 공동 호스트·체크인·집계 통계 |

기존 `free / plus / premium`과 서버 검증된 멤버십을 재사용한다. 이번 초안은 가격·상품·유료 기능의 두 등급별 배분을 변경하지 않는다. 현재 모임 자리 3/5/10은 개최+참여+잠금이 섞여 있으므로 이를 곧바로 '동시 모집 행사 수'라고 표시하지 않는다. 호스팅 수와 참여 자리의 분리, 새 한도 숫자는 유료 도구 단위의 별도 승인 대상으로 둔다. 첫 무료 단위에서는 기존 서버 한도를 유지하고 사실대로 표시한다.

복제는 참가자·신청 답변·비공개 정보를 복사하지 않고 행사 설정을 새 초안으로 만든다. 반복 일정은 무한 게시가 아니라 유한한 회차를 생성하고 회차마다 정원·취소를 분리한다. 공동 호스트 초대는 수락이 필요하며 권한 범위를 제한한다. 멤버십 만료로 이미 승인된 참여자를 내보내거나 행사 취소·안전 공지를 막지 않는다. 대기열 승격에도 참석자 동의를 유지한다.

반짝 참여자를 지속 모임에 자동 가입시키지 않는다. '다시 만나기'는 각자의 명시적 가입 동의를 받는 후속 단위다. 티켓 판매·수수료·새 결제 공급자는 이번 범위에 포함하지 않는다.

## 데이터·보안 경계

- 기존 Supabase 사용. 새로운 BaaS나 별도 계정 시스템은 만들지 않는다.
- 칠링 프로필은 공개 `profiles`와 분리해 읽기 범위를 제어한다. 소유자·해당 신청을 검토하는 호스트·감사 로그를 남긴 운영자 경로를 구분한다.
- 일정/유형은 검증 가능한 모임 상세 데이터로 추가하고, 사적인 집결 정보와 신청 답변은 공개 feed JSON에 포함하지 않는다.
- 기본 정원·승인·무료 기능을 RPC 직접 호출로도 사용할 수 있어야 한다. 유료 권한 역시 UI가 아니라 서버에서 검사한다.
- 신청 프로필 공유 동의의 범위와 버전을 기록한다. 철회·탈퇴·거절 후 호스트 접근 종료와 보존 정책을 구현 전에 정하고, 무기한 호스트 열람 권한은 만들지 않는다.
- ADR-0001의 서버 안전 분석과 운영자 감사 열람을 새 소개·질문·답변에도 연결한다. 신고/차단은 모든 등급에 적용한다. 새 분석 경로의 실제 유료 호출 테스트는 별도 비용 승인 없이 실행하지 않는다.
- 차단·신고 숨김이 칠링 카드, 상세, 프로필, 신청함, 그룹 대화에도 일관되게 적용돼야 한다. 숨겨진 항목을 캐시 응답으로 복구하지 않는다.

## 구현 순서와 완료 기준

1. 무료 기본 데이터/RPC와 권한 테스트 → 프로필과 신청 → 칠링 목록·행사 작성·운영 화면.
2. 유료 운영 도구의 등급/한도 상세 확정 → 서버 권한 → 복제/반복/대기자 → 공동 호스트/체크인/집계.
3. 동의 기반 반짝→지속 모임 연결.

각 단위는 테스트 후 별도 커밋한다. 출시 전에는 실제 기기에서 무료 계정으로 개최·신청·승인·대화를 완료하고, 비회원/다른 신청자의 프로필·답변·집결 정보 접근 차단을 확인한다. 만료 시각/시간대, 동시 승인 정원 초과 방지, 반복 클릭의 중복 처리, 유료 만료 후 운영 지속, 신고/차단 즉시 반영을 회귀 검사한다. 기존 App Review 수정본과 기능 개발 배포를 섞지 않는다.

## 디자인 참고 확인

2026-09-17 BrandKit의 글링 브랜드 확인: 종이/잉크/절제된 붉은 강조와 기존 타이포그래피를 유지한다. Luma의 화면을 복제하거나 글링을 외부 서비스로 이전하지 않는다.

- [Luma 신청 질문](https://help.luma.com/p/collect-registration-questions): 질문형 신청과 호스트 검토 구조 참고.
- [Luma 참여자 관리](https://help.luma.com/p/managing-your-guest-list): 승인 상태별 관리 참고.
- Pinterest 검색에서 이벤트 일정·발견·초대 화면 후보를 확인했으나 이미지 기반 상세 디자인 검증은 아직 하지 않았다.
- Kroma/Mobbin 검색 시도는 Serper 인증키 부재로 실패했다. Mobbin 전용 도구도 현재 연결 목록에 없어 실제 화면을 확인했다고 주장하지 않는다. UI 구현 전에 접근 가능한 공식 화면과 기존 디자인 자산으로 보완한다.

이 문서는 출시 완료나 수요 검증 결과가 아니다. 첫 검증 대상은 실제 참석과 다음 만남이며, 수익화 도입은 반복 개최 수요를 따로 확인한다.

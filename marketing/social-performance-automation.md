`targets`는 `arm:test|reference/content_id/content_sha256/selected_at`와 실제 적용 시 `applied_at/application_receipt/plan_sha256`을 가진다. `publication`은 **실제 본인 공개 UI/기존 영수증을 확인한 경우만** `platform/account/url/native_id/published_at/verified_at/content_sha256/source`를 넣는다. 예약 영수증은 별도 `reservation_receipt`이며 publication이 아니다. 해시가 없는 공개 미디어는 연결 보류다.

`observations`는 post와 동일한 `platform/account/url/content_sha256/published_at/observed_at/metrics/source/approximate`를 가진다. 원자료 path와 관측을 append하며 이전48h 수치를 최신 누적으로 교체하지 않는다. 연결된 Reels 레퍼런스 성과는 이미 연결된 RP `growth_loop.py --library <글링 전용 library>`에도 기존 방식대로 저장하고 이 보고에서 같은 observation ID/원자료를 참조한다. 별도 개인 자료를 레퍼런스 원장에 넣지 않는다.

적용 영수증은 `experiment_id/plan_sha256/account/run_id/created_at/content_id/status/before_sha256/after_sha256/change/before_after_source/guardrail_source/comparison_content_id/next_check`와 실제 local 결과 경로를 기록한다. 선정이 완료되면 위 계약의 `targets/frozen_at/comparison_receipt/guardrails_passed/confounders`도 담아 두 ID/hash와 사전 선정 근거를 보고가 그대로 이어받게 한다. 적용하지 못한 회차도 `status:held`와 구체적인 이유/다음 회차를 남겨 보고에 포함한다. 적용 상태를 승인·공개 상태로 바꾸지 않는다. 공개 영수증은 위 publication 필드와 해당 시험/대상 ID를 연결한다. 보고 작업은 가장 최신 임의 파일 하나가 아니라 해당 ID/hash의 모든 관련 적용·예약·공개 기록을 대조한다.

`decision`은 `action/rationale/observation_sources/decided_at/next_experiment_id`다.7d 비교가 미완료면 관측 보완/다음 대기를 적고 승패를 쓰지 않는다. 판정 후에는 후속 ID를 다음 미승인 생산 작업으로 넘긴다. 렌더/검사 실패 시 옛 pointer를 보존하고 오류를 회차 보고에 남긴다.

완료 확인: (1)기존 실제 native 보고·초안·예약·행사 prompt 재조회와 일정/소속 불변, (2)미공개·해시/계정 불일치·이른/늦은/누락 수치와0분모 검사, (3)보고서의 대기/실측 표시, (4)공용 GUI coordination check. 미래 공개/성과는 실제 다음 회차의 별도 검증이다.

## 저장과 보고

회차별 `marketing/reports/YYYY-MM-DD/social-performance/<run_id>/`에 실제 UI/미디어 증빙, `data.json`, `report.html`을 저장한다. 로컬 산출물을 실제 네이티브 발행/성과로 보고하지 않는다. 원본을 보존하고 다른 회차의 파일을 덮어쓰지 않는다.

`data.json`은 다음 최소 구조를 따른다. 값은 실제 확인 자료로 채운다.

```json
{
  "report_date": "YYYY-MM-DD",
  "run_id": "unique-run-id",
  "generated_at": "timezone-aware ISO time",
  "status": "partial",
  "summary": "실제 오늘 확인한 결론과 한계",
  "accounts": [
    {"platform": "threads", "account": "chalkakandupload", "status": "partial", "note": "실제 관측 범위", "observed_at": null},
    {"platform": "instagram", "account": "gling.app", "status": "partial", "note": "실제 Reels 범위", "observed_at": null}
  ],
  "posts": [],
  "comparisons": [],
  "experiments": [],
  "next_steps": [],
  "sources": []
}
```

각 post는 `id/platform/account/url/title/format/category/published_at/observed_at/content_sha256/metrics/source/observation_scope`를 가진다. 구조는 `structure:[{time,observation,source}]`, 개선은 `improvement`로 저장한다. 실제 이전 관측이 있는 경우만 `previous:{observed_at,views,content_sha256,approximate}`를 넣는다. `metrics.views` 등은 숫자 또는null이며 `approximate`를 별도로 남긴다. `comparisons`는 `account/higher/lower/basis/difference/hypothesis/change/limitation`으로 원본 URL을 연결한다. `next_steps`는 `account/target/change/hypothesis/status`를 가진다. 표본이 없으면 빈 목록과 이유를 그대로 쓴다.

```sh
python3 marketing/social_performance_report.py <data.json 절대경로> --output <report.html 절대경로>
python3 -m unittest discover -s marketing -p 'test_social_performance_report.py'
```

검증 후 전용 pointer의 시각부터 읽고, 더 최신 보고가 없을 때만 **같은 완성 데이터를** `output/design/gling-social-performance-latest.html`로 렌더한다. `marketing/social-performance-latest.json`에는 run_id·generated_at·status·원본data/report 절대경로·해시를 원자적 저장한다. 현재 pointer가 더 최신이면 HTML도 JSON도 덮어쓰지 않는다. partial 보고도 partial 표시로 최신화하되 마지막 성공한 관측은 원래 시각으로 보존한다. 일반 `marketing/reports/latest.html/json`이나 다른 계정 보고는 덮어쓰지 않는다.

개인 다음 글 작업과 행사 제작은 최신 보고의 해당 계정 활성 시험을 읽고 **각자의 기존 현재 인사이트·원고/사실/사진/음악/승인 검증을 거쳐서** 한 요소를 실제 적용·기록한다. 보고서 생성은 새 원고의 임의 승인·브랜드 템플릿 변경이 아니다. 실제 적용/공개/관측 결과는 위 계약으로 다음 보고에 이어간다.

회차 최종 응답은 한국어로 핵심 관측/개선 한두 줄과 **[일일 보고서](/절대경로/report.html)** 링크를 제공한다. localhost/테일넷·공개 artifact 발행·이메일/DM·Slack 전송을 추가하지 않는다. 별도 외부 유료 API를 호출하지 않고 기존 Codex 구독으로 분석한다.

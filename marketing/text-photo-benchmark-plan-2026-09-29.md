## 목적과 범위

튜브벤치는 영상을 분석하고, 이 플랜은 글링의 **내부 SNS 운영 자동화**에서 Threads 텍스트와 Instagram 사진·캐러셀 게시물을 분석한다. 목표는 조회수 자체보다 해외 거주 한인, 특히 **실제로 모임을 열거나 운영할 사람**과의 대화를 늘리는 것이다. 분석 결과는 @chalkakandupload의 개인 Threads 원고와 @gling.app의 정보성 Instagram 원고에 각각 맞게 변환한다. 영상은 제외하고, 글링 앱 사용자에게 새 분석 기능을 출시하는 일도 현재 범위가 아니다.

튜브벤치 실제 구현은 메타데이터·자막 등 확인 가능한 자료를 모은 뒤, 훅과 본문을 **보는 사람에게 하는 일이 바뀌는 지점**에서 가변 구간으로 나눈다. 고정된 4막을 강요하지 않고, 원문 인용이 없는 구조나 보지 못한 장면을 만들어내지 않는다. 이후 구조·경험·세계관·리듬을 분석하고 사용자 채널에 맞는 코칭을 별도로 만든다. ## 1. 입력: 사용자가 준 링크와 조회수 근거로 시작한다

사용자가 Instagram 사진·캐러셀 또는 Threads 글의 **URL**을 주면 해당 게시물만 열어 본문·사진 각 장·댓글·실제로 보이는 지표를 확인하고 분석 카드로 만든다. 가능하면 조회수 화면이나 게시물 인사이트의 숫자·관측 시점도 함께 받는다. URL만 있어도 구조 분석은 가능하지만, 조회수가 안 보이면 `조회수 미확인`으로 둔다. 비교하고 싶은 보통 글의 URL도 사용자가 주면 같은 계정·형식·게시 경과 시간을 고려해 나란히 분석한다. 링크가 없으면 후보를 찾으려고 피드를 스크롤하지 않는다. 영상 링크는 이 글·사진 분석에서 제외하고 튜브벤치 대상으로 구분한다.

첫 수동 탐색 파일럿은 [관측 기록](reports/2026-09-29/text-photo-benchmark-pilot.md)에 보존하되, 이후 표본 수를 채우기 위한 자체 검색은 하지 않는다. 받은 링크를 하나씩 정밀 분석하고, 비교 URL이 모일 때만 계정·형식·시기별 대조군을 만든다. 비교 글이 부족하면 ‘바이럴 원인’ 판정을 보류한다. 우리 계정의 기존 글은 별도 기준선으로 남긴다.

각 사례에는 원본 URL, 계정, 게시일, 관측 시각, 플랫폼/형식, 주제·지역, 공개 좋아요/댓글/인용·재게시, 확인된 조회수와 그 출처, 댓글의 내용, 광고·협찬 표시 여부를 기록한다. 비교 URL이 제공된 경우에만 공개 반응을 그 계정의 비슷한 글과 비교하고, 팔로워 규모·게시 후 경과 시간·유료 노출 여부가 불명확하다는 점을 함께 적는다. 좋아요와 댓글을 합친 임의의 ‘조회수 점수’는 만들지 않는다. 호응이 적은 비교 글도 제공되면 대조군으로 남겨 생존 편향을 줄인다.

**측정 경계:** Threads 공식 Insights API는 자신의 Threads 게시물 인사이트용이다. 다른 계정의 조회수는 공개 화면에 보일 때만 관측값으로 기록한다. Instagram의 타인 사진/캐러셀은 실제 도달·조회수·저장·공유를 일반적으로 확인할 수 없다. Meta 문서의 `view_count`는 릴스용이고 `total_views_count`는 동영상용이며, `saved_count`는 소유자/승인된 공동 작업자에게 제한된다. 따라서 Instagram 타인 사진은 ‘공개 반응이 큰 사례’이지 ‘조회수 폭발이 검증된 사례’라고 부르지 않는다. [Threads Insights](https://developers.facebook.com/documentation/threads/insights), [Instagram Media 필드](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media).

**조회수 구간은 10만·50만·100만 이상**으로 나눈다. 화면이나 해당 게시물의 인사이트에서 수치가 확인된 경우에만 `10만 이상~50만 미만`, `50만 이상~100만 미만`, `100만 이상` 중 하나로 분류한다. 사용자가 조회수 숫자만 알려주고 원본 화면을 확인할 수 없다면 `사용자 제공·미검증`이라고 함께 적는다. 숫자가 안 보이는 Instagram 사진/캐러셀은 `조회수 미확인·형식 참고`로 두며, 좋아요·댓글로 조회수를 추정하지 않는다. 저장 항목은 원본 URL·조회수 출처와 관측 시각·확인된 원문/화면·공개 지표·이미지별 관찰·댓글 근거다. 타인의 사진·문장을 글링 게시물에 옮겨 쓰지는 않는다.

## 2. 분해: 게시물마다 근거가 붙은 분석 카드 한 장

분석 단위는 Threads에서 **문장·문단**, Instagram에서 **표지·각 슬라이드·캡션**이다. 고정 구간 수나 훅 공식을 강요하지 않는다. 슬라이드 텍스트를 읽을 수 없거나 캡션이 잘리면 그 부분은 `확인 불가`로 남긴다. 사진에서 실제 보이는 구성만 묘사하고, 이미지의 출처·촬영 의도·제작 과정을 추정하지 않는다.

카드에 아래 항목을 기록한다.

1. **성과와 맥락:** 정확한 출처와 관측 시점, 공개 수치, 사용자 제공 비교 URL이 있을 때 같은 계정의 보통 글과 차이, 숨은 변수.
2. **첫 접점:** 첫 문장/첫 장의 정확한 짧은 인용 또는 묘사, 예상 독자, 제기한 문제·호기심. 관찰과 ‘왜 멈춰 읽었을지’ 가설을 구분.
3. **전개 지도:** 각 문장·문단/슬라이드의 `독자에게 하는 일 → 근거가 된 실제 표현·시각 요소 → 다음 구간으로 넘어가는 이유`를 순서대로 기록.
4. **감정·참여:** 공감·유용성·논쟁·지역 정체성·구체성의 작동 가설. 실제 댓글 3~5개가 무엇에 반응했는지 확인하고, 댓글이 없으면 반응 이유를 확정하지 않음.
5. **표현 방식:** 말투, 줄바꿈, 길이, 캡션에서 잘리는 위치. 사진은 실제 보이는 피사체·초점·여백·대비·글자 크기·읽는 순서·각 장의 정보량까지 기록. Threads와 Instagram을 같은 기준으로 점수화하지 않음.
6. **재현 가능한 패턴:** 같은 계정 또는 다른 사례에서 반복되는지, 평범한 대조 글과 무엇이 다른지. 인물·장소·이슈의 일회성 효과는 따로 분리.
7. **글링 적용:** 원문의 문장·사진·개인 경험을 가져오지 않고, **새 주제와 초안을 계정별로 제안**. @chalkakandupload에는 캐나다에 다시 온 개발자/창업자의 실제 경험과 모임장 질문이 맞는지 검토하고, @gling.app에는 확인된 행사·지역 정보 또는 제품을 만드는 과정으로 변환한다. 실제 겪었는지 모르는 개인 장면은 원고에 넣기 전에 확인이 필요하다고 표시.

분석 카드에는 `관측 사실 / 해석 가설 / 확인 불가` 세 칸을 둔다. AI가 원문에 없는 댓글·경험·조회수를 보충하면 그 카드는 폐기하거나 수정한다. 다른 사람의 사진, 캡처, 긴 문장을 새 소재로 재사용하지 않는다. 행사 카드는 [기존 공식 행사 후보 목록](instagram-event-ideas-2026-09-29.md)의 주최·일시·장소·비용을 게시 직전에 다시 확인한다.

### 작은 예시: 사용자 제공 Threads 사례

사용자가 공유한 “캐나다 진짜 개노잼이네. 대체 여긴 무슨 재미로 사는 거야?”는 **3만 조회라는 사용자 보고**가 있다. 원본 Insights를 확인한 수치는 아니다.

| 원문 구간 | 관측되는 역할 | 가능한 반응 가설 |
| --- | --- | --- |
| “캐나다 진짜 개노잼이네.” | 짧고 강한 감정으로 캐나다 생활 경험을 호출 | 동의·반박을 부를 수 있으나 실제 댓글 확인 전에는 미검증 |
| “대체 여긴 무슨 재미로 사는 거야?” | 답을 강요하지 않는 질문으로 독자에게 말할 자리 제공 | 장소·취미·사람 만나는 법을 댓글로 말할 여지 |

그 표현 자체가 조회수를 만들었다고 단정할 수 없고, 우리 계정에서 같은 불만 문장을 복제할 이유도 없다. 글링용 가설은 “혼자면 안 가게 되는 캐나다의 공연·행사”처럼 새로운 장면을 잡아, 실제 모임 경험자가 **어떻게 사람을 모았고 무엇이 어려웠는지** 묻는 것이다.

## 3. 초안·승인: 기존 운영 흐름에 붙인다

`사용자 URL 접수 → 분석 카드 → 근거가 쌓인 패턴 메모 → 계정별 새 원고 후보 → 사실·원본성·말투 검수 → 사용자 검토 → 기존 승인 큐` 순서다. 새 DB나 공개 서비스, 별도 예약기를 만들지 않는다. 현재 글링 마케팅 자동화와 `marketing/social-calendar.csv`, [개인 계정 승인 규칙](chalkakandupload-queue.md)을 재사용한다. URL이 없으면 벤치마크 분석을 건너뛴다. 처음에는 받은 URL의 허용된 공개 화면과 로컬 Markdown 기록만 사용해 분석 품질을 확인한다. 반복 입력이 실제 병목으로 확인된 뒤에만 작은 로컬 스크립트를 검토한다. 과금 가능한 AI/API 호출은 금액·조건 확인 전 실행하지 않는다.

@chalkakandupload 초안은 실제 현지 생활 장면과 모임장 질문을 자연스럽게 쓰고, 개인글마다 글링을 넣지 않는다. @gling.app Instagram 초안은 밴쿠버·토론토의 행사 정보와 동행·운영 팁 자체가 유용해야 한다. 글링을 만드는 계정의 실제 작업을 말할 수 있지만, 확인되지 않은 이용자 반응·기능·행사 참여를 꾸미지 않는다. 기존 SNS 직접 링크/설치 유도 제한과 각 계정 말투를 따른다.

사용자가 **최종 원고를 개별 승인한 것만** 기존 큐에 들어간다. 현재 브랜드 @gling.app은 로컬 초안 전용이며, 이 플랜은 발행 재개나 예약 권한을 뜻하지 않는다. 개인 Threads도 기존 고정 시간·종류별 승인 큐·오른쪽 분할 화면 규칙을 바꾸지 않는다. 2026-09-28 보고 기준 브랜드 Instagram은 최근 30일 공개 성과가 0이고 개인 Threads 인사이트의 지정 오른쪽 화면은 확인에 실패했으므로, 초기에는 ‘분석 카드 품질’만 검증하고 계정 성과 결론은 실제 관측 뒤에 낸다. [최근 보고서](reports/latest.html).

나중에 기존 자동화에 붙이더라도 맡길 일은 **사용자가 제공한 링크만** 중복 제거하고, 화면상 숫자와 본문/이미지의 확인 가능한 부분을 기록해 문장·슬라이드별 분석 카드 초안을 만드는 것까지다. 링크가 없는 회차에는 아무 사례도 수집하지 않는다. 사람이 확인할 일은 이미지·인용의 정확성, 실제 경험 여부, 행사 사실과 사진 사용 범위, 최종 말투와 발행 승인이다. 지금은 자동화 설정을 변경하지 않는다. 개인 원고 작성은 기존 규칙대로 해당 회차의 실제 Threads 인사이트를 먼저 확인한 경우에만 진행한다.

## 4. 검증: 조회수와 적합한 대화를 따로 본다

파일럿에서 분석 카드를 보고 만든 글과 평소 방식의 글을 **같은 계정·비슷한 주제/형식/게시 경과 시간**으로 비교한다. 순차 게시라 무작위 실험이 아니므로 단일 승자나 알고리즘 원인을 선언하지 않는다. 초안마다 어떤 요소를 바꿨는지 한 가지 가설 ID로 기록한다.

| 시점 | 확인할 것 | 해석 기준 |
| --- | --- | --- |
| 게시 전 | 출처가 있는 분석 카드, 원본과 다른 아이디어, 정확한 사실, 승인된 최종본 | 근거가 약하면 초안 수정·보류 |
| 게시 후 24시간·72시간·7일 | **우리 글**의 플랫폼 제공 조회/도달, 댓글·인용/재게시, Instagram에서 실제 제공되는 저장·공유, 팔로우/프로필 활동 | 누락값은 0으로 처리하지 않고 원본 지표·관측 시각 보존 |
| 대화 품질 | 해외 거주자와 모임 운영자가 실제 경험을 말했는지, 운영의 재미·어려움·모집 방식에 대한 답변 | 조회수보다 적어도 적합한 답변을 별도 성과로 기록 |
| 제품 연결 | 확인 가능한 자발적 관심, 실제 모임 개설·반복 운영 | SNS 조회·댓글을 모임 개설로 대체하지 않음 |

2주 단위로 패턴별 결과를 보고 **계속 / 수정 / 폐기**한다. 높은 조회수만 나오고 관련 대화가 없으면 후킹 방식보다 독자 적합성부터 재검토한다. 반대로 작은 조회수라도 실제 모임장 질문과 연결되면 그 대화 주제를 후속 글에 반영한다.

## 실행 순서

1. **링크 접수·기준선:** 사용자가 준 URL과 조회수 근거를 함께 기록한다. 없으면 구조만 분석한다. 비교 URL이 있을 때 계정·형식·게시 경과 시간을 맞춰 높은 글/보통 글을 짝짓는다. 개인 계정 인사이트는 기존 지정 오른쪽 화면을 확인할 수 있을 때만 읽는다.
2. **정밀 분해:** 받은 게시물의 문장·슬라이드를 분석 카드로 만들고, 서로 다른 사례에 반복되는 패턴만 남긴다. 근거와 해석을 분리한다.
3. **원고 파일럿:** 확인된 패턴에서 계정별 새 초안을 작성하고 기존 승인 흐름에 제시한다. 승인된 개인 글만 기존 슬롯에서 처리하며, 브랜드 계정은 로컬 초안으로 둔다.
4. **발행 후 학습:** 실제 발행된 원고가 있을 때만 24시간·72시간·7일 지표와 댓글 내용을 붙여 패턴을 갱신한다. URL 입력량이 커질 때 카드 초안 작성만 자동화하고 승인·발행 규칙은 유지한다.

**첫 완료물:** 출처와 관측 시점이 있는 사례 목록, 플랫폼별 대표 분석 카드, 글링에 맞게 변환한 미승인 원고 후보, 성과 관측 표. ‘바이럴 공식’이나 자동 발행 시스템은 완료물로 주장하지 않는다.

1. 브랜드의 실제 최근 원글, 현재 예약 목록의 읽은 범위, 현재 인사이트/댓글을 확인하고 증거를 저장한다. 조회 불완전·계정 불일치·미확인 제출이면 해당 슬롯 보충을 보류한다. 원장이 아닌 실제 목록을 기준으로 중복을 확인한다. 이미 예약된 본문과 시간은 보존한다.
2. 원장 `GL-BT` ID를 이어서 사용한다. 기존 shared social-calendar CSV의 `GL-P` 항목을 변환하거나 개인 계정/행사 원장을 덮어쓰지 않는다. 같은 날짜·본문 hash·native 영수증·미완료 attempt가 있으면 추가 제출하지 않는다. 새 원고를 넣기 전 최근/예약된 글을 비교한다.
3. `새로운 스레드 → 더 보기 → 예약...`으로 네이티브 달력을 연다. 새 snapshot의 정확한 연·월·일 gridcell을 선택하고 `hh/mm`을 17/30으로 설정한다. 이미 정확한 값이면 불필요한 입력을 생략한다. 월이 다르면 실제 이전/다음 달 컨트롤로 이동한다. 선택된 전체 날짜와 시각을 다시 읽는다. `완료`는 날짜 선택이며 실제 예약 저장이 아니다. 날짜 클릭 후 달력이 닫히면 현재 timestamp에서 다시 열어 확인한다. ref는 각 단계에서 갱신한다.
4. 자기 빈 작성창·계정·날짜를 확인하고 입력 전 `preparing`과 작성창 소유 run_id를 남긴다. DOM focus와 Orca의 **native focused text entry**를 함께 확인한다. AX click 성공 응답은 증거가 아니며 필요하면 현재 screenshot에서 실제 좌표/배율을 확인한다. 고정 좌표를 재사용하지 않는다. Terminal input/다른 앱 포커스이면 입력하지 않는다.
5. 여러 줄 본문은 `orca inserttext --text <literal multiline copy>`로 넣는다. 본문 `fill`은 이 호스트의 Lexical editor에서 줄바꿈을 없앨 수 있으므로 쓰지 않는다. 실제 주제 검색에 `캐`를 입력하고 현재 표시된 첫 주제/커뮤니티 결과 하나를 선택한다. 선택 전 전체 표시 순서를 저장한다. option UI에서는 정확히 첫 결과가 `aria-selected=true`인지 확인한 뒤 Enter로 적용한다. 다른 UI라면 실제 첫 결과의 정상 선택 컨트롤을 사용한다. `캐나다`와 `캐나다생활`을 두 개 붙이거나, 검색 문자열만 입력한 새 태그로 대신하지 않는다. 이 호스트에서는 DOM activeElement가 검색창이어도 `document.hasFocus()==false`이면 검색 결과가 안 보인 사례가 있었으므로 실제 표시/포커스와 결과를 확인한다. 못 읽은 목록을 읽었다고 처리하지 않는다. 입력 직후 전체 본문·줄바꿈·실제로 선택한 단일 주제/커뮤니티·작성자·예약 시각을 대조하고, 저장 후 재개방하여 같은 선택을 다시 확인한다. 2026-10-07 초기 GL-BT001의 직접 입력한 `캐나다생활` 태그 영수증은 당시 태그 저장의 증거이며, 이번 첫 검색 결과/커뮤니티 선택의 증거로 재사용하지 않는다.
6. 최종 `예약` 직전 실제 미래 시간·원고 hash·작성자·기한을 재확인한다. 원장을 새로 읽어 CAS로 자기 항목만 갱신하고, `scheduling`, `submission_kind=native_future_schedule`, `attempted_at`, run_id/page/future ISO를 temp+flush/fsync+replace로 영구 기록한다. 최종 `예약`은 **한 번만** 클릭한다. 즉시 `게시` fallback은 없다.
7. 저장 후 실제 `임시 저장본` 목록에서 그 본문이 있는 **유일한 예약**을 다시 열어 전체 본문/작성자/시간을 읽는다. “금요일” 같은 표시만으로 날짜를 확정하지 말고 timestamp의 달력을 다시 열어 선택된 연·월·일과 hh/mm까지 대조한다. 변경 없이 닫으며 `업데이트`를 누르지 않는다. 실제 영수증을 저장한 뒤만 `scheduled`로 기록한다. 공개 URL이나 native ID가 보이지 않으면 지어내지 않는다.
8. 제출 뒤 확인이 안 되면 `uncertain`으로 남기고 재전송하지 않는다. 다음 실행도 실제 목록과 원글을 읽어 해소하며 “목록에서 안 보임”만으로 발행이나 재시도 권한을 추론하지 않는다. 이미 지난 예약은 실제 자기 공개 글의 전체 본문·작성자·permalink·발행 시각을 확인한 뒤만 `published`로 바꾼다. 지연/취소/누락을 임의 즉시 발행으로 메우지 않는다.

## 보고와 검증

`marketing/reports/YYYY-MM-DD/brand-threads-automation/<unique-run-id>/`에 실제 관측·계정/소속·GUI queue 결과·조회 범위·새 예약 영수증·원장 변화·실패 단계·다음 행동을 저장한다. 공개 확인과 native 예약 저장을 구분하고, 반응/인사이트와 추정은 구분한다. 새 경험은 marketing-sales-playbook에 출처·관측일·검증 상태와 함께 추가한다.

원장 변경 후 ID/hash/계정/날짜 유일성과 영수증을 확인한다. 공동 GUI 동작을 바꿨다면 `python3 -m unittest discover -s marketing -p 'test_browser_*.py'`를 실행한다. 설정 변경은 실제 `orca automations show <id> --json`의 prompt/workspace/schedule/timezone/enabled를 읽어 검증한다. 예약 시험을 위해 자동화를 수동 실행하지 않는다. 설정 완료, 자동 회차 실행, 예약 저장, 공개 발행, 측정 결과는 각각 별도 증거다.

사용자 보고는 한국어로 짧게: 실제 예약 수/날짜, 공개 확인 수, 남은 항목과 구체적 막힘. Orca `completed`를 업무 성공으로 간주하지 않는다.

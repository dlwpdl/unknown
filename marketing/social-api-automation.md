```sh
python3 marketing/meta_media.py --intent "$INTENT" --out "$STAGING_RECEIPT"
python3 marketing/meta_api.py prepare instagram --intent "$INTENT" --receipt "$CREATE_RECEIPT" --out "$STATUS_RECEIPT"
python3 marketing/meta_api.py container instagram --receipt "$CREATE_RECEIPT" --out "$STATUS_RECEIPT"
python3 marketing/meta_api.py publish instagram --receipt "$CREATE_RECEIPT" --out "$PUBLIC_RECEIPT"
```

`CREATE_RECEIPT`는 반드시 `$PRIVATE_OPS/meta-api/<platform>/<content_id>.create.json`이다. 회차별 다른 파일로 같은 글을 재전송할 수 없다. `prepare`는 원래 슬롯 23시간 이내에만 수행하고, publish는 `FINISHED` 및 원래 시각 이후 Threads 60초/Instagram 15분 이내만 허용한다. 새 미래 예약은 로컬 원고다. API container의 수명은 24시간이므로 7일 버퍼 전체를 미리 업로드하지 않는다. 공개 재조회가 잠시 늦으면 원래 `.publish.json`의 ID를 읽고 `reconcile`로 조회한다; 다시 publish하지 않는다. 프로브의 `probe:true`는 publish가 항상 거부된다.

```sh
python3 marketing/meta_api.py reconcile threads --receipt "$CREATE_RECEIPT" --out "$RECONCILIATION"
python3 marketing/meta_api.py prepare threads --intent "$INTENT" --receipt "$CREATE_RECEIPT" --out "$STATUS_RECEIPT"
python3 marketing/meta_api.py publish threads --receipt "$CREATE_RECEIPT" --out "$PUBLIC_RECEIPT"
python3 marketing/meta_api.py reply instagram --intent "$INTENT" --receipt "$CREATE_RECEIPT" --out "$PUBLIC_RECEIPT"
```

전송 전에 전용 attempt 파일을 배타적으로 저장한다. 결과가 끊기면 `uncertain`으로 남기며 자동 재시도하지 않는다. 성공한 public readback을 원래 레코드에 병합할 때 현재 파일 hash/다른 작성자와 충돌을 확인한다. 기존 네이티브 미래 예약은 API 조회의 공개 글 목록에 아직 없다고 실패/누락으로 판정하지 않는다.

## 비공개 영상과 운영 조건

Instagram Login은 로컬 `resumable`을 지원하지 않는 것이 실제 400 응답과 공식 문서로 확인됐다. `meta_media.py`는 이미 사용 중인 글링 Supabase에만 연결하여 `sns-media`의 content hash 경로에 파일을 검증·저장하고 40분 signed URL을 발급한다. 버킷은 비공개이며 anon/authenticated/앱 관리자/사업자 모두 RLS에서 거절한다. **로컬 운영 서버만** 기존 Supabase CLI Keychain 권한으로 서버 key를 메모리에서 사용한다. 이 명령과 key 조회를 앱·웹·MCP 사업자 도구에 노출하거나 server key를 파일/클라이언트에 복사하지 않는다. stage는 글링 공식 Instagram 파일만 받는다. 다른 고객의 파일·Gling 기존 이미지/게시글 저장소는 수정하지 않는다.

G9/G10의 기존 회차에서 Meta가 `FINISHED`로 받아갔고 공개 ID가 검증된 같은 stage 파일의 hash 경로만 정리한다. source/project/로컬 master 및 공개 SNS는 보존하고, 네트워크 결과가 불확실하면 새 전송 대신 먼저 저장 경로를 재조회한다. 새 cleanup job을 만들지 않는다.

```sh
python3 marketing/meta_media.py --retire "$STAGING_RECEIPT" --receipt "$CREATE_RECEIPT" --out "$CLEANUP_RECEIPT"
```

정리는 정확한 원래 hash 경로·Meta 수신/공개 ID를 대조하고 실제 Storage 목록의 부재를 재조회한다. CDN 사본은 잠시 남을 수 있으므로 즉시 바이트 소멸로 기록하지 않는다. signed URL은 원래 40분 만료를 유지한다.

G5의 기존 회차에서 두 토큰의 refresh 명령을 점검한다. long-lived token은 발급 24시간 전 갱신 불가이며 여기서는 7일마다 갱신한다. 실제 갱신 응답+같은 계정 재조회+0600 저장을 확인한 경우만 성공이다. 만료되면 정상 재연결하며 비밀번호 로그인/인증 우회로 대체하지 않는다.

API 발행은 현재 Mac의 기존 Orca 스케줄러가 수행한다. Mac/Orca가 꺼지면 새 로컬 큐는 발행되지 않는다. 이미 Meta에 저장된 예약은 별개다. 별도 상시 cloud scheduler를 설치하거나 새 게시 일정/유료 서비스를 추가하지 않았다.

검증 근거는 private `operations/social-api-migration-2026-10-10/`다. 본인 글 조회·인사이트·댓글 조회, unpublished container 처리, 실제 정상 공개 발행·답장, 토큰 갱신과 다음 native scheduled 실행을 각각 구분한다. 시험 공개 글/댓글은 만들지 않는다.

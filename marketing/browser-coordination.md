AX 성공 응답만으로 인정하지 않고 현재 이미지로 위치/배율을 확인하며, 실제 텍스트 엔트리 영역이 아니면 `inserttext`/paste를 하지 않는다. 여러 줄은 `orca inserttext --text`를 쓰고 전체 원문·줄바꿈을 재조회한다. 당시 터미널로 들어간 자기 본문만 정확히 식별해 미제출 상태로 제거했고, 실제 예약 본문은 이후 별도로 대조했다.
5. 하나의 GUI 확인/작성 묶음을 끝내고, 자기 소유 토큰이 일치하는 잠금만 해제한다. 공식 자료 분석·이미지 렌더·긴 로컬 준비 중에는 GUI 잠금을 유지하지 않는다. 미완료 제출을 다른 작업이 이어 하게 넘기지 않는다. 새 GUI 묶음은 다시 잠금을 잡고 새 snapshot/ref를 얻는다.
6. 원글 슬롯 시작 후 첫 5분(밴쿠버 08/09/10/11/13/15/17/19의 00~04분)은 승인 원글 작업에 양보한다. 댓글·일일 초안·Instagram·행사 검증·앱 도시 작업은 이 구간에 새 GUI 묶음을 시작하지 않고 로컬 준비만 한다. 발행 시간을 옮기거나 기한 지난 슬롯을 채우는 허가는 아니다.

## 잠금 대기와 종료 처리 — 2026-10-05

사용자 “각 자동화 시작 전에 다른 작업을 확인하거나 큐에서 기다렸다가 끝나면 실행” 지시에 따른 작은 변경이다. Orca CLI의 `--precheck`는 실패 시 skipped로 끝나므로 GUI 대기는 기존 Python 도구 안에서 처리한다. 준비·렌더·자료 분석은 동시에 할 수 있지만 화면·포커스·클립보드는 한 번에 한 작업만 사용한다.

- `marketing/browser_preflight.py`의 `gui_bundle(role, run_id, deadline)`을 사용한다. `deadline`은 **절대 UTC epoch seconds**다. 댓글 회차는 첫 실행 시각+5분에서 종료 기록 시간을 남겨 잡고, 승인 원글은 해당 고정 슬롯 시작+5분보다 늦게 잡지 않는다. 대기 시간을 실행 제한에 포함한다. 큐 대기는 원래 기한 안에서만 하며, 잠금 획득 후 GUI 도구 묶음은 최대55초다. 원글의 첫5분 우선권을 먼저 확인하고 다른 역할은 그 구간에서 새 GUI 묶음을 시작하지 않는다.
- **한 번의 도구 측 Python 실행 안에서만** `with gui_bundle(...) as owner:`를 유지한다. 결과/이미지를 에이전트가 읽거나 모델이 생각하는 동안, 별도 도구 호출 사이, 긴 로컬 렌더 동안 잠금을 유지하지 않는다. 다음 묶음은 다시 대기·획득·preflight한다. 작성·제출 단계는 승인/기한/작성자/본문 확인과 영구 attempted 기록을 같은 묶음에서 끝낸다. 미완료 사용자 작업을 다른 회차에 넘기지 않는다.
- 묶음 안의 Orca 명령은 가져온 `orca(...)` 함수를 쓴다. 이 함수는 운영체제 잠금 FD를 실제 Orca 하위 프로세스에도 전달한다. preflight CLI를 하위 프로세스로 호출할 경우에도 `pass_fds=(int(os.environ['GLING_GUI_GUARD_FD']),)`를 전달한다. 서브프로세스를 백그라운드로 띄워 UI를 변경하지 않는다.
- 같은 기존 `browser-pane.lock/owner.json`에 소유자·PID·프로토콜을 기록하고, 옆의 영구 `.guard` 파일에 macOS `flock`을 건다. `.guard` 파일은 지우지 않는다. 정상 종료/예외는 `finally`에서 해제한다. 강제 종료 잔재는 **OS 잠금을 실제로 획득했고 같은 프로토콜의 기록된 PID가 사라진 경우에만** 기존 디렉터리를 보관 경로로 옮기고 복구한다. 오래된 mkdir-only 잠금·모르는 소유자·살아 있는 PID는 자동 복구하지 않는다.
- `GUI_QUEUED`, `GUI_QUEUE_RESUMED`, `GUI_QUEUE_TIMEOUT`, `GUI_RECOVERED_TERMINATED_OWNER`와 실제 기한/조회/작성 결과를 회차 영수증에 기록한다. 대기는 새 승인·늦은 발행·자동 제출 재시도·유료 호출 허가가 아니다. 모델 용량 오류나 시작 확인창도 성공으로 보고하지 않는다.

with gui_bundle('threads', 'current-run-id', time.time() + 45) as owner:

        sys.executable, '/Users/ash/Desktop/Git/unknown/mobile/marketing/browser_preflight.py',

## 원고와 보고의 분리

- 개인 Threads 일일 작업은 Threads 인사이트·원글·수신 댓글과 개인 원고만 다룬다. 예전 통합 마케팅 prompt의 Instagram/Meta/Gmail 점검·브랜드 콘텐츠 제작은 실행하지 않는다. 개인 원고를 행사 캡션으로 변환하지 않는다.
- Threads 일일 보고는 `marketing/reports/YYYY-MM-DD/personal-threads-daily/`에 저장한다. 행사 제작·검증 보고와 원장은 기존 전용 경로를 유지한다. 서로의 최신 보고나 영수증을 덮어쓰지 않는다.
- 공유 CSV를 수정할 때는 작업에 속한 ID만 바꾸고 다른 계정·승인 원고·발행 영수증을 보존한다. 저장 직전 원본이 변경됐으면 다시 읽고 대조하며, 오래된 전체 파일로 덮어쓰지 않는다. `python3 marketing/check_calendar.py`와 저장 본문 대조를 실행한다.
- Orca run의 `completed` 표시나 Codex 시작 화면만으로 업무 완료를 인정하지 않는다. 실제 단계·파일·UI readback 영수증이 있어야 해당 결과를 완료로 보고한다. 잠금 충돌·다른 화면 표시·기한 만료·Orca 오프라인·실행 시작 실패는 구분한다.

현재 확인된 문제는 운영 준비와 측정 부재다. **아직 관측하지 못한 전환율이 낮다고 진단하지 않는다.** 출시 후 모임 참여·사람을 만나는 가치를 중요하게 보라는 사용자의 최신 제품 판단도 반영한다. 첫 글·댓글은 관찰 가능한 보조 행동이지 제품 가치의 유일한 정의가 아니다.

### 3. 원고와 소재의 기준

현재 SNS에는 생활 메모·질문 자체를 주제로 사용한다. 앱 기능 소개·화면 녹화·QR·URL·홍보 배너를 소재로 만들지 않는다. 아래 제품 화면 제작 항목은 제품 자료 관리의 일반 기준이며 현 SNS 제작 과제가 아니다. 사용자의 내용 정책 변경에 맞추는 편집은 일반적인 단일 요소 실험과 구분해 변경 전후를 보존한다.

1. 고객 상황, 이번 가설, 정확한 제품 사실, 근거 화면, 주 CTA, 변경할 요소, 출력 수량을 먼저 정한다. 기본 2개 후보면 비교 가능하다. 수량 증가는 배포 용량이나 검증할 가설이 있을 때만 한다.
2. 브랜드·제품 화면·출시 상태·핵심 기능은 고정한다. 같은 실험에서는 첫 문장 등 주요 요소 하나만 바꾼다. 정확한 도시·상황으로 개인화하며 고객 경험·친분·후기·결과를 만들지 않는다.
3. 실제 앱 화면은 촬영일과 빌드/수정 근거를 `notes`에 남긴다. `asset_brief`는 제작 지시이고 완성 파일이 아니다. 완성 후 `asset_path`에 실제 파일 경로를 기록한다. 현재 Instagram 6건은 소재 제작 전이다.
4. 이미지의 글자 잘림·읽기 크기·브랜드/제품 일치·수량을 전수 확인한다. 짧은 영상은 처음부터 끝까지 재생해 대사 중복, 자막/음성 불일치, 제품 사라짐, 종료 잘림을 확인한다. 영어 단어 수 제한을 한국어 발화 시간으로 대체하지 않는다.
5. 한 작성자의 차분한 해요체를 유지한다. 실제 제작 판단이나 독자에게 유용한 구체적 상황을 넣고, 모든 글을 같은 질문형 끝맺음으로 만들지 않는다. 현재 원고가 고객 조사 결과라는 뜻은 아니다.

### 4. 도착 경로와 링크

**현재 적용:** 모든 SNS 초안은 `link_placement=none`, `link` 빈 값이다. 본문에도 URL·도메인·프로필 링크 유도를 넣지 않는다. 아래 profile/body·스토어 전환 설명은 과거 측정 정의이며 자동 복구 지시가 아니다. 기존 랜딩과 제품 범위 Gmail 읽기는 계속하되 이 원칙을 이유로 앱/랜딩 코드를 바꾸지 않는다.

- 출시 전: 소개 화면에서 확인 가능한 앱 기능과 출시 준비 상태를 안내한다. 오픈 알림 메일은 선택 행동이다. 메일 작성 창 열림과 실제 신청 메일 수신은 다르다.
- 출시 후: 공개 스토어 → 설치 → 계정/도시 선택 → 첫 유효 행동까지 실제 기기에서 확인한 링크로 교체한다. 아직 없는 설치 링크를 작성하거나 내부 테스트 링크를 공개 다운로드라고 부르지 않는다.
- `link_placement=profile`: Instagram 공용 프로필 링크. `utm_content=profile`로 고정한다. 계정 단위 유입을 개별 게시물의 클릭으로 배분하지 않는다.
- `link_placement=body`: 실제 본문에 넣는 링크. `utm_content=gl_p002`처럼 변경하지 않는 게시물 ID에 대응시킨다. GL-P002는 본문 URL도 포함했다.
- `link_placement=none`: 대화 자체가 CTA인 글. 사용하지 않는 추적 링크를 채워 두지 않는다.
- 출처/매체/캠페인: `instagram` 또는 `threads` / `organic_social` / `prelaunch`. UTM에는 이름·이메일·개인 질문을 넣지 않는다. 동일 본문의 재공유나 다음 캠페인에는 새 게시물 ID를 부여한다.
- UTM은 수집·보고 도구가 읽어야 유입 자료가 된다. 현재 글링의 웹 전환 수집/보고 접근은 검증 전이다. [Google 공식 URL 태그 안내](https://support.google.com/analytics/answer/10917952?hl=en).

### 5. 대기열·저장·발행·재시도

`social-calendar.csv`를 유일한 글링 게시 대기열로 사용한다. ID는 행 순서나 날짜가 바뀌어도 유지한다. 기존 `day`는 첫 게시일 기준의 계획이며 실제 예약 시각이 아니다.

| 필드/상태 | 기록 규칙 |
|---|---|
| `content_id` / `experiment_id` | GL-P001 등 게시 단위 ID / GL-L001 등 학습 가설. 하나의 가설이 여러 게시물을 가질 수 있음 |
| `draft` | 원고 초안. 계정·소재·출시 상태 검수가 끝난 것이 아님 |
| `ready` | 실제 작성 계정·완성 소재·문구·도착 경로 검수 완료. `account_handle`, 필요한 `asset_path`와 근거 notes |
| `scheduled` | 플랫폼에서 다시 조회한 예약 항목이 있음. `scheduled_at`은 UTC offset 포함 ISO 시각, `publish_ref`는 예약 ID/URL |
| `published` | 공개 글의 계정·본문·소재·링크를 확인. `published_at`, 실제 URL/ID 기록. 예약 ID도 notes/회차 보고서에 보존 |
| `blocked` / `cancelled` | 현재 진행할 수 없는 이유 / 의도적 취소. 기존 저장·발행 이력은 지우지 않음 |
| `notes` | 변경 이유, 확인 화면/파일, 이전 외부 ID, 다음 조치. 비밀번호·토큰·비공개 고객 원문 제외 |

예약/발행 직전에 **플랫폼의 기존 대기열·공개 글을 조회**한다. 저장 요청이 시간 초과된 경우 성공 여부가 불명확하므로 본문·계정·시간·기존 ID로 먼저 찾는다. 불확실하면 `blocked`와 이유를 남기고 같은 글을 다시 보내지 않는다. CSV 점검은 이 외부 중복 조회를 대신하지 않는다.

Threads 네이티브 예약은 **새로운 스레드 → 임시 저장본**에서 재조회한다. 2026-09-09 첫 예약 화면에는 개별 예약 ID/URL이 없어서 GL-P002의 `publish_ref`는 실제 프로필 URL이며, [관측 JSON](reports/2026-09-09/gl-p002-reservation.json)에 본문·시각·화면을 함께 보존했다. 공개 글이 생기면 실제 게시물 URL로 갱신한다. 새 원고 입력 시 빈 작성창에서 붙여넣기 이벤트를 사용한 뒤 전체 본문과 줄바꿈을 검증한다. 이번 Orca의 일반 `fill`은 Threads 편집기에서 줄바꿈 소실·덧붙임을 일으켰다.

확인된 일시적 읽기 오류에만 제한적으로 재시도한다. 같은 작업은 **최초 포함 최대 3회**, 서비스가 안내한 대기 시간을 지킨다. 인증 만료·권한 부족·비용 제한은 반복하지 않고 원인과 필요한 조치를 기록한다. 이미 성공한 항목은 재처리하지 않는다. 자동 수정으로 새 결제·더 넓은 권한·다른 계정·기존 안전 정책 변경을 택하지 않는다.

중복 스케줄러를 만들지 않는다. 계정과 도구가 준비되면 기존 Orca 네이티브 예약을 먼저 사용하고, 글링 실행 담당은 하나로 둔다. 다른 실행 환경으로 옮길 때 인증·파일·시간대·필요 도구를 확인한 뒤 기존 실행을 중지하고 새 환경에서 1회 결과를 검증한다. 맥 상시 실행 여부는 사용자가 이미 확인했으므로 매번 묻지 않는다.

### 6. 관측과 수신함

| 지표 | 실제 의미·출처 | 판단에 쓸 조건 |
|---|---|---|
| `reach` | 해당 글 인사이트에서 제공하는 고유 도달. 제공하지 않으면 빈 값 | 플랫폼 원본 명칭·게시 후 경과 시간 기록 |
| 조회/노출 | 반복을 포함할 수 있는 원본 조회/노출 수 | 도달로 옮겨 적지 않고 회차 보고서에 원본 명칭으로 기록 |
| `profile_visits` | 글별 값이 실제 제공될 때만 CSV 기록 | 계정 전체 기간 값은 계정 요약으로 분리 |
| `link_clicks` | 해당 글의 직접 링크 클릭이 확인된 경우 | 공용 bio 클릭·사이트 전체 세션은 개별 글에 넣지 않음 |
| `waitlist_requests` | 실제 수신한 자발적 알림 요청, 중복 제거 | 클릭과 구분. 출처 불명이면 게시물별 빈 값, 전체 수신 집계에 출처 미확인 표시 |
| 설치/가입 | 스토어 집계 또는 실제 앱 기록 | 설치 클릭과 설치 완료 구분; 개인정보 없는 집계 사용 |
| 첫 이용 | 실제 글·댓글 또는 모임/대화의 유효 행동을 각기 기록 | 내부/seed/심사 제외. ‘읽기’도 가치일 수 있으므로 글쓰기 강요 지표로 쓰지 않음 |
| 재방문 | 같은 신규 사용자 코호트가 정의한 기간에 다시 유효 활동 | 예: 가입 후 7×24시간 이상 관찰된 코호트의 7–8일 구간. 분모·기준일·행동 정의 고정 |

CSV의 성과 열은 **최근 관측의 요약**이다. 새 수치를 넣기 전에 이전 행과 원본 화면을 날짜별 회차 보고서에 남긴다. 24시간·72시간·7일 시점 이후 첫 실행에서 실제 경과 시간을 기록하며, 기회를 놓쳤다면 현재 누적값으로 기록하고 과거 시점의 값으로 소급하지 않는다.

- `not_collected`: 아직 수집하지 않음. 숫자 빈 값.
- `unavailable`: 권한/플랫폼/도구 때문에 수집 불가. 숫자 빈 값과 이유.
- `partial`: 일부 지표만 확인. 확인된 값만 쓰고 `observed_at`·`metric_source` 필수.
- `observed`: 의도한 관측 범위를 확인. 미제공 지표는 여전히 빈 값이며 실제 0만 `0`.

비율은 동일 글·기간·대상 범위의 분자/분모가 있을 때만 계산한다. 분모 0 또는 미확인은 비율 미확인이다. 순차 SNS 게시 비교는 무작위 A/B 실험이 아니므로 시간·노출·대상 차이를 함께 적는다. 소표본에서 승자를 확정하거나 생성된 요약을 인과관계로 표현하지 않는다.

글링 수신함이 연결되면 실제 문의·고객 질문·자발적 요청을 시스템 알림/스팸/단순 반응과 분리한다. 검색 계정·폴더/기간·메시지 ID·관측 시각을 남기고, 마지막 성공 이후를 확인하되 경계가 겹치는 메시지는 ID로 중복 제거한다. 접근 실패는 문의 0건이 아니다. 답변 초안은 내부에 남기고 외부 답장은 해당 발송 지시 범위에서만 한다. 해결·수신 거절·나중에 연락 요청·분쟁은 자동 반복 응답의 중단/보류 조건이다. 이메일 열람만으로 구매 의향을 단정하지 않는다. [Apple의 메일 활동 보호 안내](https://www.apple.com/legal/privacy/data/en/mail-privacy-protection/).

### 7. 회차 결과와 다음 반영

회차 보고는 `marketing/reports/YYYY-MM-DD/<run_id>.html`에 누적한다. 동일 파일 덮어쓰기 대신 새 실행 시각을 사용한다. 사용자 확인 화면은 HTML이며 원본 지표/에러의 근거와 이전 보고서를 연결한다. 개인정보가 있는 원문은 Git 외부 글링 저장소에 둔다.

반드시 포함할 내용: 실행 시각·범위·계정 → 실제 완료/미완료 → 글별 수치와 근거/누락 사유 → 관측 사실 → 해석·가설 → 다음 글 ID와 주된 변경 → 초안/예약/발행 중 실제 반영 단계 → 다음 확인 조건. 클릭·문의·첫 사용·재사용·지불을 별도로 보고한다.

오류에는 서비스·실행 환경·run_id·실패 단계·최초 포함 시도 횟수·마지막 성공·민감정보를 제거한 원인·다음 조치를 기록한다. 실제 오류와 테스트용 실패를 구분한다. 외부 Slack/메일 알림을 새로 추가하지 않고 우선 기존 Orca 실행 결과와 보고서에 남긴다.
